# 2602.02619v2 — daVinci-Agency: Unlocking Long-Horizon Agency Data-Efficiently

**Relevance:** low
Real overlap on topic (SFT for tool-using agents, data-quality-over-quantity, rejection-sampling filters) but the paper targets multi-turn long-horizon SWE agency on 8B–235B-class models with no small-model, quantization, or single-turn structured-output/schema-validity results, so nothing here settles a decision for a 1.2B on-device tool-calling model.

## TL;DR

The paper builds training data from chains of real GitHub Pull Requests (up to 5 linked PRs per chain) to teach long-horizon behaviors — task decomposition, cross-stage consistency, and iterative bug-fix refinement — then full-parameter fine-tunes GLM-4.6 and the Qwen3 family (4B/8B/30B-A3B/32B) on as few as 239 such trajectories, reporting large gains on SWE-bench/Toolathlon/τ²-bench. It is about constructing high-fidelity multi-turn agentic *trajectories* at large model scale, not about single-turn structured tool-call reliability or quantization, so it's mostly context rather than a directly usable method for this project.

## Techniques to try

- Rejection sampling of self-generated rollouts against a semantic-alignment threshold before using them as SFT data: "With a strict threshold of $s\geq 0.8$, the evaluator provides textual feedback for up to three refinement iterations. Trajectories failing to meet this standard are discarded" (Section 4.3, Evaluator for Rejection Sampling). This is a generic data-quality-gate idea that could inform the SFT data-mix ablation stage, though the evaluator here is itself a large LLM (GLM-4.6) scoring semantic alignment to a ground-truth patch — a different setup from schema/JSON validity checks.
- Small, curated, high-quality SFT sets can beat much larger noisy ones: fine-tuning "on merely 239 daVinci-Agency samples" outperformed baselines trained on 66k (SWE-Smith) and 59,939 (CodeAgent) samples (Table 1, Section 5.2). Relevant as a data-efficiency data point for the project's "higher-rank or full SFT with a data-mix ablation" stage, though at a very different model scale and task type.

## Baselines & datasets used

- SWE-Smith (66,000 samples, SWE-agent scaffold, Claude-3.7-Sonnet rollouts), CC-Bench (260 samples, Claude Code scaffold), AFM CodeAgentDataset (59,939 samples) — all external agentic SFT datasets used as comparison baselines (Section 5.1, Baselines).
- Evaluation benchmarks: SWE-bench Verified, Toolathlon, τ²-bench (retail/airline), DS-1000, SciCode, and AgencyBench Code — all at 8B+ model scale (GLM-4.6, Qwen3-4B/8B/32B/30B-A3B, DeepSeek-v3.2, Kimi-K2-Thinking, Qwen3-235B). No result below 8B parameters is reported except Qwen3-4B, which actually shows the fine-tuning barely moving the average (0.164 → 0.168) and dropping τ²-bench-airline (0.285 → 0.255) — see Pitfalls below.

## Pitfalls / negative results

- Skipping the rejection-sampling filter is catastrophic, not just suboptimal: "training on raw, unfiltered trajectories leads to a catastrophic performance degradation, with the average score plummeting to 0.205—significantly below the base model's 0.405" (Appendix B, Table 5), versus 0.421 with the filter applied. This is a strong caution that unfiltered self-generated SFT data can actively unlearn base capabilities — relevant to this project's own SFT data-mix ablation and general-ability-erosion concerns, even though the domain (code-patch semantic alignment) differs from schema/tool-call validity.
- At the smallest model size tested (Qwen3-4B, still 3x this project's 1.2B target), the technique's gains are marginal or negative: overall average moved only 0.164→0.168, and τ²-bench-airline actually dropped (0.285→0.255) (Table 2, Section 5.4). The paper does not explain this weak result at small scale, and there is no data at 1–2B scale at all — a real gap for this project's size regime.
- $\text{daVinci-Agency}_{\text{SinglePR}}$ (single-PR, no cross-stage chain) underperforms the full chained version despite similar or larger data volume (2786 samples, AVG 0.315 vs. 0.475 for the 239-sample chained version) — evidence that structure/dependency in training data matters more than raw sample count for the long-horizon behaviors targeted, but this doesn't directly transfer to a single-turn tool-call reliability objective.

## Metric / eval choices

- Uses an LLM-as-judge (GLM-4.6) with a fixed threshold ($s \geq 0.8$) as both the rejection-sampling filter for constructing SFT data and (separately) the evaluator/user-simulator for τ²-bench — i.e., a model-scored signal is used to select and grade data. This is the kind of "model-scored stored reward" pattern this project's standing constraints explicitly bar from reuse as a training signal; worth flagging as a pattern to avoid replicating directly, though the paper uses it for offline data filtering rather than an RL reward.
- Benchmarks chosen (SWE-bench, Toolathlon, τ²-bench, DS-1000, SciCode, AgencyBench) are all long-horizon, multi-turn, execution-verified tasks — none evaluate first-attempt schema validity, malformed-tool-return flagging, or quantized throughput, so none of this project's specific target metrics (BFCLv3, IFEval, flag-rate/false-flag-rate) are addressed or informed by this paper.

## Open questions for our project

- The paper offers no evidence at the 1–2B parameter scale or under quantization, so it cannot inform whether rejection-sampling-filtered SFT data would help or hurt a 1.2B model's schema validity or flag-rate targets — this remains open.
- Is the "small curated dataset beats large noisy one" result (239 vs. 66k samples) scale-dependent in a way that would reverse or diminish at 1.2B parameters, given the paper's own weak Qwen3-4B result? Worth watching for follow-up work that tests this at smaller scale.
