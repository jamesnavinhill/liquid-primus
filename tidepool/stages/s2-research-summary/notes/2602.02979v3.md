# 2602.02979v3 — CPMöbius: Iterative Coach–Player Reasoning for Data-Free Reinforcement Learning

**Relevance:** low
Real topical overlap with the project's GRPO/RLVR rung of the candidate ladder, but the paper's core contribution — a data-free Coach–Player curriculum for math reasoning at 1.5B–7B scale — targets a setting (no labeled data, self-generated curricula, math competition benchmarks) that doesn't match this project's situation (curated tool-call/JSON data already exists, target task is structured-output reliability, not open-ended math reasoning).

## TL;DR

CPMöbius trains two cooperating LLMs — a Coach that proposes math problems calibrated to the Player's current skill, and a Player that solves them via GRPO on majority-vote pseudo-labels — entirely without external training data or ground-truth labels, and shows this beats other "data-free" RL baselines (RENT, R-Zero) on math benchmarks for 1.5B–7B models. It's a curriculum-generation and self-play-stabilization idea, not a tool-calling, structured-output, or quantization paper.

## Techniques to try

- GRPO recipe used here for verifiable-but-unlabeled rewards: pseudo-labels come from majority voting over n sampled rollouts, then reward is agreement with the pseudo-label — "$r_{i,j}=\mathbb{I}[y_{i,j}=y_{i}^{*}]$, where $y_{i}^{*}$ is the majority-voted pseudo-label" (Section 4.2). Not directly needed here since this project has ground-truth schema/execution checks, but relevant if the project ever needs a reward signal for held-out malformed-tool-return cases where "correct" isn't unambiguous.
- Difficulty-filtered curriculum batching: keep only training examples whose empirical solve-rate under multi-sample rollout falls in a "pedagogically optimal zone" — "retaining only problems whose accuracy scores fall within the pedagogically optimal zone of $0.2\leq acc_{i}\leq 0.8$" (Section 4.1). This is a generic curriculum-filtering idea that could translate to filtering GRPO training batches for the tool-call/schema-validity rung by keeping only prompts of intermediate difficulty for the current checkpoint, rather than a method specific to this paper's domain.

## Baselines & datasets used

- Baselines: RENT (entropy-minimization self-reward) and R-Zero (adversarial self-play challenger/solver), both "data-free" unsupervised RL methods for math reasoning.
- Player base models tested: Qwen2.5-Math-1.5B, OpenMath-Nemotron-1.5B, Qwen2.5-Math-7B-Instruct, OctoThinker-3B-Hybrid-Zero — all in the ≤8B range relevant to this project's scale, but all math-specialist models, not general-purpose or tool-calling models.
- Eval benchmarks: AMC, AIME 2024/2025, Minerva, MATH-500, OlympiadBench — none relevant to BFCL, IFEval, or structured-output evaluation.

## Pitfalls / negative results

- Adversarial self-play instability is called out as the reason CPMöbius avoids a challenger/solver design: "Such an adversarial setup is prone to instability, collapsing into nonsensical or unlearnable proposed tasks for RL training" (Section 1). Relevant caution if this project ever considers self-play-style generation of adversarial/malformed tool-call examples rather than curated ones.
- "R-Zero failed on OpenMath-Nemotron-1.5B, failing to be trained as a Challenger as required by R-Zero" (Section 5.2) — a concrete case where a self-play RL baseline broke down on a strong SFT-initialized model, a scale/starting-point sensitivity worth remembering if considering self-play methods on an already-instruction-tuned base like LFM2.5-1.2B-Instruct.
- Ablations show every component matters and removing any one hurts: disabling Coach updates, Coach warm-up, or the difficulty filter each degrades average accuracy (28.8 → 25.3 / 23.7 / 24.9 on Qwen2.5-Math-1.5B, Table 2) — i.e., the naive/simpler version of this method underperforms substantially, a caution against assuming a stripped-down variant of a multi-part RL recipe will retain most of the benefit.

## Metric / eval choices

- Reports both an "Overall Average" and an "OOD Average" (all benchmarks except the one used as the held-out validation/reward signal), explicitly to guard against the validation set being reused as a training signal — a pattern analogous to this project's own base-vs-guardrail matched-rerun discipline, though applied to a different metric (math accuracy, not schema validity).
- Uses rule-based/verifiable rewards (answer-matching, majority-vote pseudo-labels) rather than a learned or model-scored reward model throughout, consistent with this project's "no model-scored stored reward may be reused as a training signal" constraint, though this is a generic RLVR framing rather than a novel technique.

## Open questions for our project

- None of this paper's numbers, datasets, or ablations transfer directly to BFCL, IFEval, schema validity, or quantization — it never touches tool calling, JSON output, or low-bit inference, so it doesn't help settle any of the project's pre-registered questions directly.
- No instruction-like text addressed to a reader/agent was found in the paper; it reads as a standard research paper throughout.
