# 2605.05819v1 — HCInfer: An Efficient Inference System via Error Compensation for Resource-Constrained Devices

**Relevance:** low
Real topic overlap (quantization accuracy recovery via LoRA-style error compensation, per-matrix/per-layer sensitivity to quantization) but the core contribution is a CPU-GPU heterogeneous serving system that requires offloading a large LoRA compensation pool to host DRAM — inapplicable to a project whose whole point is a single self-contained 4-bit GGUF under 1.5 GB running entirely on one GPU with no offloading, and the paper never touches structured output, tool-calling, or instruction-following.

## TL;DR

HCInfer keeps a quantized LLM backbone on GPU but offloads a LoRA-style low-rank "error compensation" branch (which approximates the quantization residual ΔW) to a CPU process, computing it asynchronously so the CPU work hides behind GPU execution; it also allocates compensation rank per-matrix/per-layer based on measured sensitivity. It recovers 1.7–5.2% downstream accuracy (ARC/MathQA/MMLU) versus plain GPTQ/llama.cpp quantization on Qwen3-30B-A3B and Llama-3.1-8B, while claiming up to 10.4x throughput over full-precision offloading baselines — but this is a serving-system paper, not a training or evaluation-metric paper.

## Techniques to try

- Sensitivity-aware dynamic rank allocation for LoRA-style quantization-error compensation could inform where a quantization-aware distillation/training pass should concentrate capacity: "different weight matrices exhibit different sensitivities to quantization error compensation... dynamic rank allocation can achieve more effective accuracy recovery than static strategies under the same computation budget" (§1). Not directly applicable to a fixed 4-bit GGUF export with no runtime compensation branch, but the underlying idea (protect the most KL-sensitive layers/matrices more) is a general principle worth carrying into whatever QAT/distillation step is used.

## Baselines & datasets used

- Baselines: GPTQ and llama.cpp pure quantized (GPU-only) inference; vLLM, llama.cpp, and Hugging Face Accelerate full-precision CPU offloading (§5.1).
- Datasets/tasks: ARC-Easy, ARC-Challenge, MathQA, MMLU (downstream accuracy) plus WikiText2 and C4 (perplexity) (§5.1).
- Models: Qwen3-30B-A3B (MoE, 4-bit GPTQ) and Llama-3.1-8B (dense, 3-bit GPTQ, GPU VRAM artificially capped at 8GB) (§5.1) — the Llama-3.1-8B numbers are the ones at or below the project's relevant scale, though still 8B not 1.2B.

## Pitfalls / negative results

- "aggressive low-bit quantization still leads to significant accuracy degradation" even with existing PTQ/QAT methods (§2.1) — a general warning that low-bit (here 3–4 bit) quantization has a real accuracy cost that compensation only partially recovers (e.g., Llama-3.1-8B INT3 GPTQ drops ARC-Challenge from 53.92% full-precision to 46.02%, and HCInfer only recovers to 50.93%, Table 1) — full recovery to full-precision level is not achieved even with their method.
- The offloading approach is fundamentally bandwidth-limited: "offloading performance is fundamentally limited by I/O bandwidth, restricting throughput in practical deployments" (§2.2) — this is exactly the failure mode our project avoids by shipping a fully-resident 4-bit GGUF, so this paper's core system is solving a problem the project doesn't have.
- Their method requires substantial host DRAM (256GB in their test rig) and a full LoRA compensation parameter pool "approach[ing] the size of the original model" (§3.2) — completely impractical for the target consumer 8GB-GPU deployment envelope where the whole point is a sub-1.5GB single file.

## Metric / eval choices

- Accuracy is measured only on general knowledge/reasoning benchmarks (ARC-Easy/Challenge, MathQA, MMLU) and language-modeling perplexity (WikiText2, C4) — no instruction-following, tool-calling, or structured-output evaluation of any kind, so it gives no direct evidence on this project's core question of whether quantization damages structured output/instruction-following more than knowledge.
- Per-matrix sensitivity is measured via KL divergence between full-precision and quantized-substituted output distributions (§4.3.2) — a reusable diagnostic technique (not a training signal) for identifying which layers matter most under quantization, potentially useful for deciding where to protect quality during the project's 4-bit conversion step.
