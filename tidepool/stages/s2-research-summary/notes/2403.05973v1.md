# 2403.05973v1 — Calibrating Large Language Models Using Their Generations Only

**Relevance:** low
Real topic overlap (predicting when an LLM's output is wrong, and calibration metrics like AUROC), but the method — a separate auxiliary DeBERTa model trained on clustered embeddings — doesn't fit a project that needs the target 1.2B model itself to learn to flag bad tool returns via SFT/DPO/GRPO, not via a bolt-on classifier.

## TL;DR

The paper proposes APRICOT: train a small auxiliary model (DeBERTaV3) to predict a target LLM's confidence purely from its question+answer text, using calibration targets derived by clustering question embeddings and taking per-cluster accuracy, so no access to logits or model internals is needed. On TriviaQA/CoQA with Vicuna-7B and GPT-3.5, this auxiliary model beats sequence-likelihood and verbalized-uncertainty baselines on AUROC for detecting wrong answers, though verbalized uncertainty sometimes wins on raw ECE.

## Techniques to try

- None directly transferable: the core mechanism is an external auxiliary classifier, not a training signal applied to the target model, which conflicts with this project's constraint that the flagging behavior be instilled in the model being fine-tuned rather than reused as a stored/external reward. Still, the clustering-based target construction ("we create clustered sets $\mathcal{C}_{m}$ of inputs with similar sentence embeddings" / "Calibration targets are then obtained by using the observed accuracy per set" — Section 3.2) is a candidate way to generate *difficulty-stratified* labels when building a probe set of malformed-vs-well-formed tool returns, if the project ever needs harder negatives grouped by similarity rather than i.i.d. sampling.

## Baselines & datasets used

- TriviaQA (12k train / 1.5k val / 1.5k test) and CoQA, both closed/open-book QA — far from the project's tool-calling/JSON domain.
- Models: Vicuna v1.5 7B (white-box) and GPT-3.5-turbo-0125 (black-box) — both larger than the project's 1.2B target and not evaluated at any smaller scale.
- Baselines compared: raw sequence likelihood, Platt-scaled likelihood, verbalized uncertainty (percent and 7-point qualitative scale, with/without CoT).

## Pitfalls / negative results

- "the qualitative verbalized uncertainty does not work reliably for the smaller Vicuna v1.5 model" and "the generations do not always contain the desired confidence expression, as visible by the low success rate" (Section 4.2) — i.e., asking a ~7B model to self-report confidence in words is unreliable, and by extension likely worse at 1.2B; relevant as a caution against relying on the LFM2.5 model verbalizing its own uncertainty as the "flag" mechanism.
- "even when taking the generated confidence expression, their ability to distinguish potentially correct from incorrect LLM responses remains at or close to random level" (Section 4.2) — verbalized uncertainty's AUROC is weak even when it's emitted.
- Clustering-based calibration targets need "a sufficiently expressive sentence embedding model and a large enough number of data points"; when unavailable, the simpler binary (correct/incorrect) target "can even outperform the clustering variant in some settings" (Limitations, "Clustering.") — a reminder that fancier target construction isn't always better than a simple binary label.

## Metric / eval choices

- Calibration/detection metrics used: ECE (10 bins), smooth ECE (smECE, avoids binning via RBF kernel), Brier score, and AUROC for misprediction detection — AUROC framed exactly as "a binary misprediction detection task based on the confidence scores" (Section 4.2), which is conceptually close to the project's flag-rate/false-flag-rate framing for malformed tool returns, even though the domain differs.
- Statistical significance via the ASO test (τ=0.35, α=0.1) plus bootstrap standard errors — a more rigorous significance-testing approach than a single point estimate, worth considering when comparing candidate rungs on the flag-rate/false-flag-rate pair.

## Open questions for our project

- Does a clustering-based, difficulty-stratified way of picking calibration/eval targets generalize to a schema-validity or malformed-tool-return setting, or is QA correctness too different a signal from JSON/schema conformance for the embedding-cluster trick to transfer?
- The paper's strongest results are for AUROC-style misprediction detection, which maps loosely onto the project's flag-rate/false-flag-rate pair — worth checking whether AUROC over confidence scores is a cleaner unifying metric than the two separate rate thresholds (0.80/0.10) the project has pre-registered.
- No instruction-injection concerns were found in the paper; it reads as a straightforward research paper throughout.
