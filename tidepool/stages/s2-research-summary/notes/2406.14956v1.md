# 2406.14956v1 — Unlocking the Global Synergies in Low-Rank Adapters

**Relevance:** medium
A LoRA rank-allocation and architecture-search method that could squeeze more accuracy out of the same LoRA parameter budget, but it is only validated on OPT-350M/RoBERTa-scale encoders doing GLUE classification, never on generation, tool-calling, or structured output.

## TL;DR

The paper proposes HeteroLoRA: instead of giving every LoRA module the same rank, use cheap zero-cost proxies (GRAD-NORM worked best) to score each module's saliency and only enable the top ~25% at a higher rank, re-scoring dynamically every few training steps. It also adds "LoRA-adapted shortcut connections" (extra low-rank residual/cross-layer paths) to widen the search space, and reports both tricks beat homogeneous LoRA at matched parameter budgets on small GLUE tasks.

## Techniques to try

- Dynamic saliency-based rank allocation instead of uniform LoRA rank per module: "the modules ranking top 25% are enabled with rank r=8 until the next HeteroLoRA search" ("Appendix B.1") — could be applied to the project's LoRA SFT step to get more out of a fixed trainable-parameter budget.
- GRAD-NORM as the saliency proxy of choice: "we observe that dynamic HeterLoRA achieves better performances than static HeteroLoRA, with GRAD-NORM performing the best and surpassing the baseline" ("Section 3.2") — cheap to compute (32 batches), no extra inference cost once search is done.
- LoRA-adapted shortcut connections (residual + cross-layer, rank-r low-rank linear paths with LayerNorm after) as an additional low-rank capacity source when LoRA modules alone have "saturated": "shortcuts foster further performance improvement by developing global synergies across layers" ("Section 3.3").

## Baselines & datasets used

- OPT-350M (and RoBERTa-large, Gemma-2B for some hyperparameter tables) fine-tuned with LoRA on GLUE subsets MRPC, RTE, SST-2 (and MNLI/QQP/BoolQ/CB/COPA/Alpaca appear only in hyperparameter appendix tables, not in the main results).
- Baseline is homogeneous LoRA at rank r=2 applied to all modules, matched for total trainable-parameter count against the sparse higher-rank HeteroLoRA configs.
- "We apply LoRA to the query layer W^Q and the value layer W^V as experiments show that applying these LoRA modules to these two layers effectively improves model performance" ("Section 3.1") — an ablation (Appendix A) found Q+V is the best pair of attention projections to adapt at fixed budget, better than K, O, or all four.

## Pitfalls / negative results

- Static (search-once, then freeze) HeteroLoRA underperforms dynamic (periodic re-search): with SYNFLOW, static HeteroLoRA scored "78.7 (-5.1)" vs. the r=2 baseline of 83.8% on MRPC — a clearly worse proxy/strategy combination that the paper flags rather than hides.
- Search frequency for dynamic HeteroLoRA shows no consistent pattern: "no particular performance pattern across the search frequency can be easily observed" ("Appendix E") — meaning the extra hyperparameter (search interval) doesn't have an obvious default and needs per-task tuning, which is an added tuning burden rather than a free win.
- All positive numbers are single-digit-percent absolute accuracy gains on small GLUE classification tasks with an OPT-350M backbone; nothing here has been shown at billion-plus scale, on generation tasks, or under a quantization/deployment constraint — none of which map cleanly onto the project's BFCL/IFEval/schema-validity metrics.

## Metric / eval choices

- Accuracy on MRPC/RTE/SST-2 (GLUE), median over 5 seeds for MRPC, mean over 3 seeds elsewhere — a classification accuracy metric, not applicable directly to the project's structured-output/BFCL/flag-rate metrics.

## Open questions for our project

- Would GRAD-NORM-based dynamic module selection transfer to a decoder-only generation task with BFCL-style metrics, or does it only help discriminative classification where the loss signal is a clean scalar per example?
- The shortcut-connection extension requires architectural surgery (extra low-rank residual/cross-layer paths plus re-inserted LayerNorm) tuned specifically for OPT-350M's post-LN Transformer block; it is unclear how or whether this maps onto LFM2.5's hybrid gated-conv + GQA architecture, and the added complexity/engineering cost seems hard to justify for a project whose ladder starts at plain LoRA SFT.
- No instruction to the model was found in the paper text; nothing flagged here.
