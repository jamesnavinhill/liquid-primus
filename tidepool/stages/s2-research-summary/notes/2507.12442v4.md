# 2507.12442v4 — Characterizing State Space Model and Hybrid Language Model Performance with Long Context

**Relevance:** low
A systems-profiling paper on TTFT/TPOT/memory/energy scaling of Transformer, SSM, and hybrid architectures over very long contexts (up to 220K tokens) on consumer/edge GPUs; it never measures accuracy, tool-calling, structured output, or GGUF/CPU quantization, so it grounds none of this project's training or accuracy targets, only some deployment-side intuitions.

## TL;DR

The paper benchmarks Transformer, SSM (Mamba/Mamba-2), and hybrid (Zamba2, Hymba, Falcon-H1) models on an RTX 4090 and a Jetson Orin Nano, showing SSMs/hybrids win on memory and latency at long context (tens to hundreds of K tokens) while Transformers win at short context. It also does an operator-level latency breakdown showing SSM-scan kernels dominate runtime, especially on edge GPUs. None of this touches the fine-tuning, tool-calling, or quantized-accuracy questions this project needs answered.

## Techniques to try

- The open-sourced profiler ("SSM-Scope") does operator-level latency/memory breakdowns per model; could in principle be adapted to sanity-check the 4-bit GGUF throughput-floor requirement on the RTX 2080 Super target, but it targets raw PyTorch/CUDA kernels, not GGUF/llama.cpp, so this would need non-trivial adaptation ("The framework is designed to be backend-agnostic... It can be extended to support various inference frameworks like vLLM, TensorRT-LLM, or ONNX-Runtime" — Section III-E).

## Baselines & datasets used

- Models compared: Transformers (Qwen2.5 0.5B/1.5B, Phi-3-mini 3.82B, Llama-3.2 1B, TinyLlama 1.1B, GPT-Neo 125M), SSMs (Mamba and Mamba-2, 130M–2.8B), hybrids (Zamba2 1.2B/2.7B, Hymba 1.5B, Falcon-H1 0.5B/1.5B) — all evaluated in BF16 (Table II, Section III-B).
- Synthetic long-context inputs styled on LongBenchV2/BABILong-like data; no accuracy benchmark suite beyond a small side-experiment on MMLU, Hellaswag, Winogrande, ARC-C, TruthfulQA for one size class (~1.5B).

## Pitfalls / negative results

- Weight-only quantization does not fix long-context memory scaling for attention-containing models: "comparing Qwen2.5-0.5B using GPTQ... reduced the weight size by 3.6x (from 942 MB to 260 MB)... Despite the weight compression, the maximum supported sequence length for Qwen only increased slightly (from ~57k to ~59k)" because activation/KV-cache memory, not weights, dominates at long context (Section IV-A). Relevant caution: quantizing LFM2.5's attention blocks alone won't much extend usable context if activation/cache memory dominates.
- Hybrid models can carry implementation artifacts unrelated to architecture that hurt latency: "in Zamba2, functions like torch.is_nonzero return boolean values that require an explicit memory copy from the GPU to the CPU, which inherently triggers the synchronization bottleneck" (Section IV-C2) — a reminder that throughput regressions in a shipped hybrid model may come from framework glue code, not the core operator.
- Pure SSM (Mamba-2) trails a same-size Transformer badly on knowledge/ICL tasks: "Mamba-2 lags behind Qwen2.5 by about 25 points (36.3% vs. 61.1%)" on 5-shot MMLU (Section II-A) — a data point (at ~1.5B scale) for how much attention-free architectures give up on knowledge-heavy tasks, though LFM2.5 already includes GQA blocks specifically to avoid this gap.

## Metric / eval choices

- Core metrics: Time-to-First-Token (TTFT, prefill latency), Time-per-Output-Token (TPOT, decode latency), throughput (1/TPOT), peak GPU memory, and energy (via nvidia-smi power draw × time) — all measured at batch size 1 to model single-user on-device inference (Section III-D, III-E).

## Open questions for our project

- The paper's quantization schemes (GPTQ for Transformers, Quamba2 W4A8 for Mamba) and backend (native PyTorch/CUDA) are unrelated to the 4-bit GGUF/llama.cpp path this project needs; it's unclear whether any of the memory/throughput trends here transfer to GGUF quantization on a consumer GPU.
- LFM2.5's core primitive is gated short-convolution, not the Mamba/Mamba-2 selective-scan kernels profiled here — the operator-level bottleneck findings (SSM-scan dominates >55% of edge latency) may not apply to LFM2.5's architecture at all.
- No instruction-like or injected text was found in this paper; it reads as a standard systems paper throughout.
