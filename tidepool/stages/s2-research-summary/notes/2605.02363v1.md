# 2605.02363v1 — When Correct Isn't Usable: Improving Structured Output Reliability in Small Language Models

**Relevance:** medium
Directly studies the correctness-vs-format-compliance gap and constrained-decoding costs that motivate our project's schema-validity metric, but the method itself is inference-time prompt optimization on 7–9B/GPT-4o models with no fine-tuning, so it informs rather than settles our LoRA/DPO/GRPO plan for a 1.2B model.

## TL;DR

The paper shows that 7–9B open models (and GPT-4o) can have near-perfect math task accuracy but 0% "output accuracy" (correct JSON) under naive or minimally-specified system prompts, because of model-specific formatting quirks (markdown-fence wrapping, unescaped LaTeX). It introduces AloLab, a black-box iterative system-prompt optimizer (using Claude Sonnet 4.5 as the analyzer/optimizer) that fixes most of this without touching model weights, and shows constrained decoding is a costly, sometimes-degrading alternative.

## Techniques to try

- Explicitly forbid markdown-fence wrapping in the system prompt / training data targets rather than assuming a JSON instruction is sufficient: "Output ONLY a raw JSON object – no markdown, no code blocks, no extra text. ... Do NOT wrap your response in ‘‘‘json‘‘‘ or any other formatting." (Appendix A.1, AloLab epoch 2 prompt) — this single fix took Gemma 2-9B from 0% to ≈80% validation output accuracy on GSM8K.
- For fields that need mathematical/symbolic content inside JSON strings, avoid LaTeX-style backslash notation, which breaks JSON escaping; prefer plain-text encodings: "For fractions: use "a/b" format (e.g. "3/4") – For square roots: use "sqrt(n)" format ... – For expressions: use plain text algebra" (Appendix A.2) — raised Llama 3.1-8B's MATH output accuracy from 8.5% (REFERENCE) to 39.0%.
- Treat "first-sample schema validity" as a joint metric of task correctness and parseability, not two separate numbers — matches our own sub-criterion: "output accuracy: task_accuracy × json_valid. ... a response that is mathematically correct but structurally invalid cannot be consumed by a downstream system, making it operationally equivalent to a wrong answer." (§2.2)

## Baselines & datasets used

- GSM8K (arithmetic word problems) and MATH (advanced math, 7 subjects × 5 levels), with a fixed JSON contract (`reasoning` + `answer` fields).
- Models: Llama 3.1-8B Instruct, Gemma 2-9B IT, Qwen 2.5-7B Instruct (all 7–9B, served via cloud BF16 inference, no fine-tuning), plus a GPT-4o generalization probe on GSM8K only.
- Five prompting/decoding strategies compared: NAIVE (no system prompt), REFERENCE (minimal hand-written JSON prompt), CONSTRAINED (vLLM JSON-grammar decoding, GSM8K only), REF+CONSTRAINED, and ALOLAB (iterative optimizer, 5 runs/model/dataset with bootstrap CIs).

## Pitfalls / negative results

- Naive prompting produces 0% valid JSON regardless of underlying competence: "NAIVE prompting (no system prompt) achieves up to 85% task accuracy on GSM8K but 0% output accuracy across all models and datasets." (Abstract)
- A minimal, realistic hand-written format prompt (REFERENCE) is not a safe baseline: it gave 0% output accuracy for Gemma 2-9B and for GPT-4o on GSM8K, both due to systematic markdown-fence wrapping (§4.2, §4.7).
- Constrained decoding is not a free fix: "3.6×–8.2× latency overhead and in several settings degrades task performance substantially" (Abstract), and for Gemma specifically, "52.4% of outputs are exact duplicates under this strategy" (§4.2) — a degenerate-repetition failure mode induced by grammar constraints, directly relevant if our project ever considers constrained decoding as a fallback.
- Even after prompt optimization, a residual "format-execution inconsistency" persists: json-valid, reasoning-correct outputs with a wrong `answer` field value, verified at "1.5–1.8% of remaining AloLab failures" by an independent LLM judge — a concrete example of the reasoning/answer-field decoupling failure mode that could resemble a "flag rather than assert" gap in our own tool-call outputs.
- One model (Qwen) shows an intrinsic, prompt-independent generation instability: a "double-escaped LaTeX (`\\boxed{}`) pattern is reproducible without AloLab: Qwen generates it under any prompt that permits LaTeX in the answer field, including REFERENCE" (§6, Limitations) — illustrates that some structured-output bugs are architecture/tokenizer-specific and not prompt-fixable, a caution for our own 65K-vocab model.
- Enforcing structure can quietly cost task accuracy: "the task accuracy recovered by the fallback parser under REFERENCE ... is 47.5%, while AloLab mean output accuracy is 34.27%" for Qwen on MATH (§5) — a measurable format-task tension worth watching for in our own schema-validity vs. task-accuracy tradeoff.

## Metric / eval choices

- Primary metric is `output accuracy = task_accuracy × json_valid`, deliberately separated from task accuracy so format failures aren't hidden by a fallback answer-extraction heuristic (§2.2).
- Statistical rigor via paired McNemar tests per run (29/30 significant at p<0.05) and 5 independent runs with 95% bootstrap CIs to expose run-to-run optimization variance, rather than reporting a single point estimate (§4.6, §6).
- Used an independent LLM judge (Gemini 3 Flash) to verify a failure category instead of trusting a regex heuristic, which the paper found over-counted by roughly 10–15 percentage points (15–21% regex estimate vs. 1.5–1.8% judge-verified) — a useful precedent for calibrating any auto-graded flag-rate metric in our own eval.

## Open questions for our project

- Does the markdown-fence-wrapping / LaTeX-escaping failure mode observed here at 7–9B (and GPT-4o) get worse or better at 1.2B, where instruction-following is weaker and the vocabulary (65,536 tokens) differs from these models' larger vocabularies?
- Could an AloLab-style black-box prompt-optimization pass be run cheaply as a pre-fine-tuning step, to rule out prompt-level format fixes before spending LoRA/DPO/GRPO budget on failures that are really just prompt-phrasing issues (e.g. an un-suppressed markdown fence)?
- The paper's meta-agent ablation shows optimizer capability drives result quality and variance (Claude Sonnet 4.5 mean 84.15%, std <1pp vs. Claude 3 Haiku mean 61.0%, std 21.8pp, §4.8) — a reminder that any LLM-based grading or synthetic-data-generation step in our own pipeline is similarly sensitive to which model does the grading/generation, even though our project bans reusing a model-scored reward as a training signal.
