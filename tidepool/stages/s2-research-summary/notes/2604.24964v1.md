# 2604.24964v1 — Odysseys: Benchmarking Web Agents on Realistic Long Horizon Tasks

**Relevance:** low
The paper is entirely about frontier-scale (Opus 4.6, GPT-5.4, Qwen-3.5) multimodal computer-use agents on long-horizon web browsing, with no content on small-model post-training, quantization, structured tool-call schema validity, or BFCL-style evaluation, so nothing here is directly actionable for post-training a 1.2B on-device model.

## TL;DR

Odysseys is a new 200-task benchmark of long-horizon, multi-site web browsing tasks (derived from real Chrome history), graded with a rubric-based LLM-judge instead of binary pass/fail. Even the best frontier computer-use agent (Opus 4.6) only reaches 44.5% perfect-task success, and the paper is focused on agentic web navigation, not on tool-call schema formatting, quantization, or small-model instruction following.

## Techniques to try

- None transfer directly. The one idea with tangential relevance is the rubric-decomposition approach to grading partial success on complex tasks ("we generate a structured set of rubrics to evaluate partial progress" — Section 3.3), which is conceptually similar to per-axis grading but is built entirely on an LLM-judge, not a programmatic schema/execution check, which conflicts with this project's "no model-scored stored reward" constraint if considered as a training signal.

## Baselines & datasets used

- Frontier API models: Opus 4.6, GPT-5.4, Sonnet 4.6, GPT-5.4-mini, evaluated on Odysseys and OSWorld's runner.
- Open-weight baselines relevant by class only in that they are also "small-ish" open models, though far above 1.2B: Qwen-3.5-9B, Qwen-3.5-4B, Qwen-3.5-35B-A3B, UI-TARS-1.5-7B — "Qwen-3.5-9B model performing the best amongst the open weights CUAs that we evaluated" with only 13.5% perfect-task rate (Table 2/4), none near the 1.2B scale this project targets.

## Pitfalls / negative results

- The paper explicitly finds trajectory-level binary LLM-as-judge grading is unreliable for complex/long tasks: "this binary approach becomes increasingly unreliable as tasks grow more complex and action sequences lengthen" (Section 1) — a general caution about relying on single holistic LLM judgments for complex multi-step evaluation, loosely relevant to this project's own held-out probe design for malformed tool returns.
- Notes that using rubric/LLM-judge scores as a reward signal for RL is proposed as future work — "This also introduces a meaningful reward signal for training weaker models with reinforcement learning, which would be a strong direction for future work" (Section 4.1) — but this is exactly the kind of model-scored stored reward this project's standing constraints prohibit reusing as a training signal.
- Even frontier models plateau hard on harder/higher-fanout tasks and "current agents struggle not only with long sequential horizons, but also with high-fanout task structure" (Section 4.3), a finding about multi-step web agents that doesn't map onto this project's single-turn tool-call prediction unit.

## Metric / eval choices

- Introduces "Trajectory Efficiency" (rubric score per step) as a first-class efficiency metric alongside success rate — an evaluation-design idea (pairing a quality score with an efficiency denominator) that is conceptually adjacent to this project's throughput-floor requirement, but the underlying quantities (agent steps vs. decode throughput) are not the same thing.
- Uses Cohen's kappa, precision/recall/F1, and accuracy against human labels to validate an automated metric's trustworthiness (Table 3) — a general methodological pattern (validate an automated judge against human agreement) that could inform how the flag-rate/false-flag-rate probe in this project is sanity-checked, though the paper's judge is gemini-3.1-flash-lite-preview scoring open-ended web rubrics, not schema/tool-call correctness.

## Open questions for our project

- None of this paper's benchmark, models, or findings bear on the pre-registered claims (BFCL, IFEval, quantization retention, throughput) or the candidate ladder (LoRA/SFT/DPO/GRPO/quantization) for this project.
- No instruction-like text addressed to the reader was found in the paper; it reads as a standard benchmark paper.
