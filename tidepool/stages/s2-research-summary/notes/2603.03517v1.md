# 2603.03517v1 — MMAI Gym for Science: Training Liquid Foundation Models for Drug Discovery

**Relevance:** medium
Same architecture family and same SFT+GRPO recipe shape the project will consider, but the domain (molecular/drug-discovery reasoning), model size (2.6B, not 1.2B), and metrics (TDC/FGBench/retrosynthesis) are entirely off-target from tool-calling/structured-output work, so it informs recipe design without settling any pre-registered claim.

## TL;DR

Liquid AI and Insilico Medicine co-authored this paper (so treat the self-reported numbers with the usual first-party discount, and note several benchmarks also involve Anthropic models scored by the same team). They fine-tune LFM2-2.6B with SFT followed by GRPO-based RFT on a large multi-task chemistry/biology data suite ("MMAI Gym"), and report that this specialized 2.6B model matches or beats much larger generalist and specialist models on drug-discovery benchmarks. It confirms the LFM2 hybrid architecture (ShortConv + GQA) at a larger scale than our 1.2B target and gives concrete SFT/GRPO hyperparameters, but says nothing about tool calling, JSON/structured output, quantization, or on-device throughput.

## Techniques to try

- Two-stage recipe: SFT first, then GRPO-based RFT on the *same* tasks/prompts as SFT — "Online RFT was performed using Group Relative Policy Optimization (GRPO, Shao et al. (2024)), using the same tasks and prompts as in SFT." (Appendix A, RFT) — directly analogous to the candidate ladder's SFT → GRPO step.
- Reward decomposition into a generic format-compliance term plus a task-specific correctness term: "In addition to these rewards, each task perceives its own task-specific reward. In each case, the reward function considers both an answer-formatting component and a correctness component." (§3.3) — a pattern worth mirroring for schema-validity + execution-correctness reward design.
- Length-tolerant answer matching to force terse, schema-like outputs: for classification, "$r_{\text{qa}}=\mathbbm{1}_{||a|-|g||<3}+\mathbbm{1}_{a=g}-1$ ... ensuring that the model only outputs the provided choice (e.g., "True") without any additional justification" (§3.3, Classification) — a cheap way to punish verbose/non-conforming answers without a full grammar/parser.
- Concrete GRPO hyperparameters at small-model scale: "group-size of $8$, with $16$ groups per global batch, resulting in a batch-size of $128$... maximum sequence length of $16,384$... high sampling temperature of $1.4$ to encourage generation diversity... KL-regularization with $\beta=0.4$... AdamW with a constant learning rate of $1\text{x}10^{-6}$ and weight-decay of $0.05$" (Appendix A, RFT) — a starting point if the project reaches the GRPO rung of its ladder, though tuned for a 2.6B model on a very different task mix.
- Data augmentation via representation-shuffling to avoid overfitting to one surface syntax: "we randomly convert SMILES ... to SELFIES ... and vice versa" and "non-canonical random traversal both for user input and model output" (§3.2) — the general idea (vary surface syntax of a structured format during training so the model learns the underlying schema, not one serialization) could translate to varying JSON key order/whitespace/quoting during SFT for tool calls.

## Baselines & datasets used

- Base model isolate-the-effect baseline: unmodified LFM2-2.6B evaluated on every benchmark to isolate the gain from MMAI Gym training (Tables 1–4) — same "matched base rerun" logic the project's pre-registered claim uses.
- Compares against much larger generalist/specialist models, including TxGemma-27B (10x+ larger) and proprietary frontier models (GPT-5.x, Claude 4.5/4.6, Gemini) as upper-bound references, and open chemical-specialist LLMs (ChemLLM, LlaSMol, ether0, NatureLM) as domain baselines.
- Uses public benchmarks TDC (Therapeutics Data Commons), FGBench, MuMO-Instruct, and USPTO-50K-test plus an internal OOD benchmark (URSA-expert-2026) — none of these are relevant eval sets for tool-calling/agentic work, but the "held-out + OOD benchmark" evaluation discipline is a pattern worth copying for guardrail-metric regression testing.

## Pitfalls / negative results

- Reward-shaping side effect the paper itself flags as a workaround rather than a solved problem: a pure length-based reward was needed because some tasks have no reasoning trace, causing the model to answer immediately — "This results in a behavior where the model sometimes output an answer immediately after a question, which hampers the sequences generated during reinforcement learning post-training. To mitigate this, we encourage the model to generate longer sequences ... $r_{\text{think}}=\min(1,-1+|o|/{2500})$" (§3.3) — a reward term keyed purely to output length is a plausible reward-hacking vector (padding reasoning to hit the token count) and is not evaluated for whether it caused degenerate verbose outputs.
- Even after multi-task RFT, the specialized model still loses to non-LLM specialist baselines on some regression tasks: "our model does not yet consistently beat the specialized TDC SOTA in regression tasks like Clearance or VDss, where specialist non-LLM models still maintain a lead" (§4.5) — a reminder that narrow-task RL specialization is not guaranteed to close every gap, even in-domain.
- The paper explicitly states that naive scale-up or reasoning tokens alone don't help: "Simply increasing model size or introducing reasoning tokens does not yield significant performance gains" (Abstract) — consistent with the project's own skepticism about brute-force scale, but offered with no ablation isolating "reasoning tokens alone" from the rest of the recipe.

## Metric / eval choices

- Robust-aggregation-over-repeated-sampling protocol: each test example is evaluated multiple times over paraphrased prompts and augmented inputs, then aggregated by "median for continuous values, majority vote for categorical" (§4.1) — a variance-reduction technique that could apply to the project's malformed-tool-return probe if per-item sampling noise turns out to be large.
- No first-token-parse-only metric analogous to the project's "first-attempt schema validity, no retry/repair/grammar" sub-criterion; this paper's parsing always happens through an explicit `<answer>` tag extraction rather than raw JSON/tool-call parsing, so the eval methodology doesn't transfer directly to the structured-output problem.

## Open questions for our project

- The paper reports GRPO hyperparameters (group size, KL beta, temperature, LR) tuned for a 2.6B model on a ~200-task chemistry corpus; it's an open question how much of that (especially the unusually high temperature 1.4 and KL beta 0.4) would carry over to a 1.2B model doing GRPO over schema-validity/execution-correctness rewards on tool-calling data.
- Because Liquid AI is a co-author here and several LFM2 architecture claims (ShortConv/GQA efficiency figures in §2) are self-reported without third-party replication, and because this paper also scores current Anthropic/OpenAI/Google models on its own OOD benchmark, all cross-model comparisons in this paper should be read as one lab's internal benchmarking rather than independently verified results.
- No instruction in the paper was directed at the reader/agent; it is a straightforward technical report.
