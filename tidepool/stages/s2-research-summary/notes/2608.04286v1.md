# 2608.04286v1 — Eliciting Intrinsic Hallucinations in LLMs via Semantically Equivalent Adversarial Attacks

**Relevance:** low
Real topical overlap (small-model faithfulness/hallucination robustness, includes 1B–8B models) but the threat model is adversarial paraphrase attacks against RAG context-faithfulness, not tool-call schema validity, malformed-tool-return flagging, quantization, or throughput — nothing here settles a decision in this project's plan.

## TL;DR

The paper builds a benchmark that paraphrases RAG queries (keeping meaning strictly fixed via bidirectional-entailment or embedding-similarity constraints) using adapted jailbreak-style optimizers (GCG, AutoDAN, PAIR, SRA, SECA) to see if the exact same question, reworded, can make a model ignore its retrieved context and hallucinate. It finds that this happens a lot, even in frontier closed-source models, and that faithfulness degradation does not track model scale.

## Techniques to try

- None directly transferable: this is an attack/evaluation framework for RAG faithfulness under paraphrase, not a training or fine-tuning method, and it targets a different failure mode (context-unfaithfulness) than this project's structured-output/tool-call reliability target.

## Baselines & datasets used

- Attack methods adapted from the jailbreak literature: "GCG (Zou et al., 2023)", "AutoDAN (Liu et al., 2024)", "PAIR (Chao et al., 2025)", "SRA (Lian et al., 2025)", and "SECA (Liang et al., 2025)", each retargeted from eliciting harmful output to eliciting an "Unable to answer" / unfaithful response.
- Evaluated open-source models directly relevant in scale to this project: "the instruction-tuned variants of Llama 3 (1B/3B/8B) (Grattafiori et al., 2024), Qwen 3 4B (Yang et al., 2025), and Gemma 3 1B (Team et al., 2025)", plus closed-source Gemini-2.5-Flash-Lite, GPT-5-nano/mini/chat, and MiniMax-2.1.
- Datasets: FaithEval (counterfactual split), ANAH-v2, and FailSafeQA (finance long-context QA), all recast as free-form generation with a fixed retrieved context.

## Pitfalls / negative results

- "we do not observe any general trends between model sizes and attack success rates, even as we see conventional accuracy improving with scale" — i.e., bigger models are not obviously more robust to meaning-preserving input perturbations, only more accurate on clean inputs. Relevant caution if this project assumes fine-tuning improvements will "just scale."
- "significantly degrade contextual faithfulness (by up to 50% for GPT-5-mini)" under black-box, no-gradient-access attacks — even frontier proprietary models were not robust.
- Token-level attacks (GCG, AutoDAN) had low attack success and very high perplexity (unnatural text), whereas LLM-generation-based attacks (PAIR, SECA) and a minimal-suffix method (SRA) achieved much higher success at low perplexity — meaning the more "natural-looking" the adversarial input, the more effective, which is the opposite of what a naive input-perplexity filter defense would assume.
- Failure-mode breakdown shows most white/gray-box-induced failures are abstention-type ("Unable to answer" was literally the optimization target), but black-box attacks shifted failures toward reasoning errors instead of abstention — suggesting different attack access levels produce qualitatively different failure signatures, not just different rates.

## Metric / eval choices

- Two custom metrics worth knowing about if this project ever needs a faithfulness/robustness eval: Adversarial Accuracy (AA, fraction of paraphrased queries still answered faithfully) and Attack Success Rate (ASR, fraction of originally-correct examples that flip to unfaithful after paraphrase), both gated on an LLM-judge semantic-equivalence check so degenerate paraphrases don't count.
- They validate their LLM-judge (Gemini-2.5-Flash-Lite) against human annotation: "Cohen's κ of 0.680 and 0.639" for semantic equivalence and "0.799 and 0.860" for hallucination detection — a reasonable data point for how much to trust an LLM-judge for a binary faithfulness/correctness label, relevant background if this project uses an LLM judge anywhere in eval (though the brief prohibits using a model-scored signal as a *training* reward, this is judge-for-eval only).

## Open questions for our project

- The paper's "flag vs. hallucinate" framing (abstention as one of five failure axes) is adjacent to this project's "flag rather than assert" sub-criterion, but the mechanism is inverted: here abstention is itself counted as an attack success (a failure mode), whereas this project wants the model to abstain/flag when a tool result is garbage. Worth noting that the same behavior (abstaining) can be either a governance signal or a failure, purely depending on whether the input actually warranted it — a reminder that a "flag rate" metric alone (without checking it fires on the right inputs) can be gamed by an overly abstention-prone model, exactly the concern the brief's paired false-flag-rate metric already guards against.
- No instruction-like text directed at the reader was found in the paper; it is a standard research paper throughout.
