# 2607.05378v1 — CompactionRL: Reinforcement Learning with Context Compaction for Long-Horizon Agents

**Relevance:** low
The paper's core problem (RL-training multi-turn context compaction for long-horizon coding agents at 30B–750B MoE scale) does not match this project's single-turn, 1.2B-model, structured-output prediction unit, so nothing here is directly actionable, though the RL/GRPO design discussion is tangentially relevant background.

## TL;DR

CompactionRL trains an agent to jointly generate task actions and its own context summaries under PPO, so it can keep working past a fixed context budget by compacting old history instead of truncating. It is validated on SWE-bench Verified and Terminal-Bench 2.0 using GLM-4.7-Flash (30B-A3B) and GLM-4.5-Air (106B-A30B), and is described as deployed in the RL pipeline for GLM-5.2 (750B-A40B) — all far larger and multi-turn/long-horizon compared to this project's single-turn 1.2B on-device model.

## Techniques to try

- None transfer cleanly. The method addresses a problem (context exceeding budget across many agent turns within one task) that does not exist for this project's "one agent turn" prediction unit; there is no compaction/summarization need at the scale or task shape this project targets.

## Baselines & datasets used

- Training data: "We use open-source training data from SWE-Dev (Wang et al., 2025)" — a coding-agent trajectory dataset, not tool-call/schema/JSON data relevant to this project.
- Evaluation: SWE-bench Verified (200 sampled tasks) and Terminal-Bench 2.0, run in the Harbor container environment with the Terminus-KIRA agent scaffold — neither benchmark is BFCL-style single-turn structured tool calling.

## Pitfalls / negative results

- Reported train/test mismatch: "CompactionRL is trained for compaction-enabled execution, and its gains do not consistently transfer to single-window evaluation when compaction is disabled. This indicates a train–test mismatch and limits its direct use in settings without test-time compaction." This is a useful general RL caution (training regime must match eval regime) but the specific mechanism (compaction) doesn't apply to this project.
- On group-wise RL methods: "If each compacted segment is treated as an optimization sample, then a group of G rollouts no longer yields G rollouts, but ... segments ... rollouts with more compaction events would be repeated more times in the group statistics and would receive disproportionate weight." This is a GRPO pitfall specific to variable-length multi-segment trajectories — this project's candidate GRPO step is single-turn, so the failure mode as described doesn't apply, but it's a reminder that GRPO's group-normalization assumptions can silently break under non-uniform sampling structure.
- Ablation: removing summary-token training from the RL objective hurts compacted-inference performance, and removing token-level loss normalization causes larger degradation than removing cross-trajectory GAE (Table 4: 66.8→60.0 SWE-bench Verified without token-level loss vs. 66.8→63.0 without cross-trajectory GAE, on GLM-4.5-Air-SFT, 106B-A30B) — illustrates that loss-weighting bugs under uneven sequence/segment lengths can matter more than credit-assignment bugs, a generic RL-training lesson but demonstrated only at 106B scale on a task structure this project doesn't have.

## Metric / eval choices

- Uses Pass@1 accuracy on SWE-bench Verified and Terminal-Bench 2.0, averaged over 2 evaluation runs — not applicable metrics for this project's BFCL/IFEval/schema-validity targets.

## Open questions for our project

- None of this paper's mechanisms (trainable compaction, cross-trajectory GAE, token-level loss for segment-length imbalance) map onto a single-turn tool-call prediction task; confirms that GRPO's group-normalization pitfalls are a real, documented failure mode in the literature (worth keeping in mind generically when implementing the project's GRPO stage) but this paper is not the right source for how to avoid reward hacking on a schema-validity reward specifically.
- No instructions-to-the-reader text was found in the paper; it reads as a standard research paper throughout.
