# 2504.20168v1 — MICE for CATs: Model-Internal Confidence Estimation for Calibrating Agents with Tools

**Relevance:** medium
The decision-theoretic framing for when to execute vs. abstain on a tool call is directly useful for our flag/false-flag targets, but the core MICE method (intermediate-layer decoding + a separate BERTScore model at inference) adds compute overhead that conflicts with our single-8GB-GPU, 4-bit GGUF deployment target and answers a different question (confidence in the model's *own* generated call) than ours (detecting a *bad tool result* coming back).

## TL;DR

The paper trains a small external classifier (logistic regression or random forest) on features extracted by decoding each transformer layer's hidden state with the unembedding matrix ("logit lens") and comparing each layer's partial output to the final output via BERTScore, plus the model's raw token probability. This classifier estimates whether a generated tool call is correct, and the estimate is used to decide whether to execute the call at all — evaluated with a new cost-sensitive metric (expected tool-calling utility) rather than just calibration error.

## Techniques to try

- Frame the execute/abstain decision as a minimum-Bayes-risk threshold on a calibrated confidence, not a fixed cutoff: "the minimum Bayes risk (MBR...) decision can be calculated; it is to execute the predicted tool call if and only if the estimated confidence $\hat{p}$ is above the threshold... $\tau \stackrel{\rm def}{=} \frac{\text{tn}-\text{fp}}{(\text{tp}-\text{fn})+(\text{tn}-\text{fp})}$" (§3.2) — this is a general recipe for turning our flag-rate/false-flag-rate targets into a single risk-weighted threshold instead of two separately-tuned numbers.
- Raw token probability alone is a poor confidence signal but a cheap, always-available feature: "including formatting tokens, which are always present in the tool call, leads to increased noise and a less accurate estimate of confidence, so we omit the tokens associated with formatting" (§2, Raw Confidence Feature) — worth doing regardless of whether we adopt MICE, if we ever want a lightweight logit-based confidence signal for flagging.
- Simple post-hoc calibration on top of raw confidence (histogram regression, or Nadaraya–Watson kernel regression) recovers most of the smECE improvement cheaply, without needing model internals: "HRE and NWKR both degrade quickly toward 0 as risk increases... MICE models also degrade, but more slowly" (§5) — HRE/NWKR are a much lower-overhead fallback than full MICE if we want any calibrated confidence signal at all.

## Baselines & datasets used

- Simulated Trial and Error (STE) dataset (Wang et al. 2024): 50 APIs, English queries, GPT-3.5-turbo-generated tool calls verified by execution feedback; MICE trained on 1,500 examples, validated on 750, tested on 750.
- Models: Llama3-8B-Instruct, Llama3.1-8B-Instruct, Llama3.2-3B-Instruct (all evaluated via 8-shot in-context learning, not fine-tuned) — the 3B result is the closest scale to our 1.2B target, though still ~2.5x larger and used purely as a frozen backbone for feature extraction, not as the model being trained.
- Baselines: raw confidence (product of token probabilities), Histogram Regression Estimator (HRE), Nadaraya-Watson Kernel Regression (NWKR, same procedure used to compute smECE itself).

## Pitfalls / negative results

- Raw model token-probability confidence is described as dangerous at exactly the risk levels we care about: "raw confidence performs dangerously poorly at and above moderate risk levels" (§5) — a plain "flag if token probability is low" heuristic is unlikely to hit our 0.80 flag-rate / 0.10 false-flag-rate targets without calibration.
- "MICE requires access to model internals, ruling out some of the most capable current LLMs, which are closed" (§9 Limitations) — not a problem for us since LFM2.5 is open-weight, but the method also implicitly requires keeping full hidden states and a second encoder model (DeBERTa-xlarge-mnli, used for BERTScore) resident at inference time, which is a real cost against an 8GB GPU / GGUF-4-bit budget the paper never discusses.
- Zero-shot generalization to unseen APIs is a real degradation, not a null result: "MICE does worse in this setting, but only degrades to the level of HRE and NWKR models trained on the full data" — i.e., the model-internals signal's advantage evaporates on tools it hasn't seen, which is relevant if we expect our tool set to grow after training.
- Feature ablation shows raw confidence alone dominates the useful signal for the linear model: "confidence is the most important feature in both MICE models: roughly 3 times as important as other features in MICE RF and 2 times as important as other features in MICE LR" (§6) — the elaborate intermediate-layer machinery buys comparatively little beyond calibrating the raw confidence, at least on this dataset/task.
- Never actually tested on the failure mode we care about (malformed/garbage tool *results* the model must flag) — only on whether the model's *own generated call* is correct against a gold reference; treat any transfer to our "flag garbage tool return" sub-criterion as unverified.

## Metric / eval choices

- Smooth ECE (smECE; Błasiok and Nakkiran 2024) as the calibration metric — replaces fixed histogram binning with Nadaraya-Watson kernel regression, avoiding the standard ECE criticism that a trivial always-predict-base-rate classifier scores perfectly calibrated.
- Expected Tool-Calling Utility (ETCU), a new cost-sensitive metric parameterized by fp/tp/tn/fn utilities, evaluated at three fixed risk settings (fp = -9, -1, -1/9, giving thresholds τ = 0.9, 0.5, 0.1) plus an AUC over all τ ∈ (0,1) — directly analogous to sweeping a flag-rate/false-flag-rate tradeoff curve rather than reporting a single operating point.

## Open questions for our project

- Could the MBR threshold formula (§3.2, Eq. 2-3) give us a principled way to set our flag-rate ≥ 0.80 / false-flag-rate ≤ 0.10 pair as a single cost ratio, rather than tuning them independently?
- Is a lightweight post-hoc calibration (HRE/NWKR on raw token confidence) enough for our "flag garbage tool return" signal, avoiding the extra inference-time cost of full MICE (per-layer decode + external BERTScore model)?
- The paper's zero-shot-to-new-API degradation suggests our flagging behavior should be re-validated whenever we add new tool schemas post-training, not assumed to transfer.
