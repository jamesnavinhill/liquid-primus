# 2509.05899v1 — X-SQL: Expert Schema Linking and Understanding of Text-to-SQL with Multi-LLMs

**Relevance:** low
Real topical overlap (SQL is one of the named specialization domains, and the paper uses QLoRA SFT on 7-8B instruction models), but the paper's actual contributions — schema-linking retrieval accuracy and multi-LLM ensembling on Spider — don't bear on this project's core questions of quantized structured-output reliability, malformed-input flagging, or throughput/vocab trade-offs at 1.2B.

## TL;DR

X-SQL fine-tunes a 7B open-source model (CodeQwen1.5-7B) with QLoRA to pick the right database tables for a query ("schema linking"), adds a prompted (not fine-tuned) natural-language schema-explanation step, and assigns different backbone LLMs to different pipeline stages, reaching 84.9% execution accuracy on Spider-Dev. It's a full multi-agent SQL pipeline built from 7-34B open models rather than a study of a single small on-device model's tool-calling/structured-output behavior.

## Techniques to try

- Dedicated SFT for a narrow structured sub-task massively outperforms few-shot prompting: schema-linking recall went from 0.326 (3-shot ICL) to 0.891 (SFT) on the same metric ("SFT ... yielding gains of 0.565 on $R_{e}$ and 0.614 on $R_{s}$" — Appendix D, Table 8). Supports starting the candidate ladder at LoRA SFT rather than relying on prompting alone.
- QLoRA hyperparameters used for 7-8B decoder-only SFT, as a reference point (far larger model than LFM2.5-1.2B, but a concrete starting config): "LoRA Parameters: Rank=128; Alpha=256, Target Modules=Q, K, V, Dropout=0.1" with "Learning Rate: 1e-4", "Train Batch Size: 32", "Epoch: 1" (Appendix B).
- Inference-time self-consistency for a retrieval-style sub-task: shuffle the candidate schema/foreign-key order and take the union of outputs across repeated samples, gaining a further +0.031 $R_{e}$ / +0.023 $R_{s}$ on top of SFT (Appendix D, Table 8) — cheap accuracy at the cost of extra inference passes.

## Baselines & datasets used

- Spider (Yu et al. 2018): 8,659 train / 1,034 dev entries across 200+ databases, plus a 2,147-entry test split across 34 databases — none of this is the project's tool-calling/BFCL or IFEval-style evaluation surface.
- Backbone models compared for the schema-linking SFT task: Qwen2-7B-Instruct, llama-3-sqlcoder-8B, deepseek-coder-7b-instruct-v1.5, CodeQwen1.5-7B-Chat, and Flan-T5-XXL (11B, encoder-decoder) — all well above the project's 1.2B target scale.

## Pitfalls / negative results

- A retrieval metric can be gamed by doing nothing: "The $R_{s}$ score will default to 1 if the entire database schema is input without any schema linking," which is why llama-3-sqlcoder-8B posted a "seemingly perfect" 0.999 $R_{s}$ while its exact-match $R_{e}$ was only 0.713 (Backbone SFT Model Benchmarking). This is a direct analogy for the project's own concern about single gameable metrics — it's the same reason the brief pairs flag-rate with false-flag-rate rather than trusting one number alone.
- The 11B encoder-decoder Flan-T5-XXL underperformed every 7-8B decoder-only model on schema linking (0.722 $R_e$ vs 0.891 for the best decoder-only model), i.e. more parameters and a different architecture family did not help this structured-selection task.
- Multi-LLM ensembling (different backbone LLMs per pipeline stage) is the paper's headline lever for the last few points of accuracy, but this project's standing constraints put ensembling explicitly out of scope, so that portion of the paper is not transferable here.

## Metric / eval choices

- Schema linking is scored with paired recall metrics $R_e$ (exact table-set match) and $R_s$ (gold tables are a subset of predicted tables) rather than a single number — worth noting as another instance of a two-sided metric pair, structurally similar to this project's flag-rate/false-flag-rate pairing, even though the underlying task (table retrieval) is unrelated to malformed tool-call detection.
- End-to-end correctness is measured with Execution Accuracy (exact match of SQL execution result vs. ground truth), a strict pass/fail metric with no partial credit or first-attempt-only framing — unlike this project's "no retry, no repair" first-sample-parses schema-validity metric.

## Open questions for our project

- Nothing in this paper addresses quantization, decode throughput, vocabulary size effects, malformed-tool-return flagging, or reward hacking with a schema-check reward — the questions this project's notes are meant to settle. Treat this paper as informative background on SQL-specialization technique only, not as evidence for any of the pre-registered claims or sub-criteria.
- All reported numbers are from 7B-34B open models; the paper gives no indication of whether QLoRA-based schema-linking gains would hold, degrade, or vanish at 1.2B parameters, which is the scale this project actually cares about.
