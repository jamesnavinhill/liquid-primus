# 2502.14905v1 — Think Inside the JSON: Reinforcement Strategy for Strict LLM Schema Adherence

**Relevance:** high
Directly demonstrates the project's candidate-ladder end-state (GRPO with verifiable rewards for schema adherence) on a similarly-sized model (Qwen2.5-1.5B), including a two-stage RL-then-SFT reward recipe and a size-matched comparison showing bare small distilled models fail at this task.

## TL;DR

The authors train a 1.5B-parameter model ("ThinkJSON") to reliably convert unstructured text into schema-valid JSON using GRPO with two custom, non-model-scored rewards (schema key/value match + JSON length similarity, and a binary `<think>`/`<answer>` tag-format check), followed by a short SFT polishing stage. On a ~6.5K-row structured-extraction benchmark, this pipeline beats much larger models (DeepSeek R1 671B, Gemini 2.0 Flash) on mean field-match percentage and noise, using only ~20 GPU-hours (8×H100) for RL and ~3 hours (1×A100) for SFT.

## Techniques to try

- Two-stage recipe: pure GRPO/RL first to build reasoning ability from a base model ("R1-Zero" style), then a separate SFT pass on a smaller reasoning-trace dataset to "polish" schema-specific edge cases — matches the project's ladder ordering of SFT before GRPO but suggests RL-then-SFT (rather than SFT-then-RL) is also viable ("Subsequently, we performed supervised fine-tuning on a separate 10K reasoning sample dataset, focusing on refining schema adherence for downstream tasks." — Abstract).
- Reward design is fully programmatic/string-based, not model-scored: a key-value matching fraction plus JSON-length similarity for content, and a separate binary reward for correct `<think>`/`<answer>` tag structure ("The format check enforces correct usage of specialized tags... The binary reward (0 or 1) simplifies reinforcement signals, focusing exclusively on structural correctness rather than content fidelity." — Section 3.3.2). This is compatible with the project's "no model-scored stored reward" constraint.
- Synthetic data construction pipeline for training data when no real schema corpus exists: generate filled + blank schema pairs with a larger model, then render the filled schema as varied unstructured "narratives" (paragraphs, tables, ASCII/XML/PDF-like layouts) to force robustness to input formatting diversity ("We then produce unstructured text reflecting the same content as the filled schema—but presented in varying layouts... and table formats (ASCII art, XML/HTML-like snippets, simulated PDF extraction, etc.)" — Section 3.1).
- Reasoning-trace generation for the SFT dataset via a separate, larger teacher model reverse-engineering how each schema field was derived from text, rather than hand-labeling ("engaging a distilled DeepSeek R1 Qwen 32B to explain—step by step—how each schema field is populated" — Section 3 method overview).

## Baselines & datasets used

- Base/policy model: Qwen 2.5 1.5B (via a distilled DeepSeek-R1-Qwen checkpoint lineage), trained with GRPO ("Train R1-Zero reasoning model from Qwen 2.5 1.5B base model using RL... and synthetic unstructured-structured pair dataset" — Section 3).
- Data-generation models: Qwen 14B/32B for synthetic structured/unstructured pairs; distilled DeepSeek R1 Qwen 32B for reasoning-trace generation (both larger than the trained model — teacher models are not deployable on-device, noted as unavailable for this project's constraints).
- RL dataset: 20K unstructured-to-structured samples; SFT dataset: 10K reasoning samples.
- Evaluation baselines compared: Original DeepSeek R1 (671B), distilled DeepSeek R1 Qwen-1.5B, distilled DeepSeek R1 Qwen-7B, Gemini 2.0 Flash (70B) — all much larger than the project's 1.2B target except the 1.5B distilled variant.
- Eval set: "a structured data extraction benchmark involving ∼6.5K rows" (Section 4) — domain/composition not otherwise specified, likely not directly reusable.
- Training tooling: Unsloth framework for SFT/SFT+LoRA on a single A100 (~3 hours) — a concretely cheap, replicable SFT setup.

## Pitfalls / negative results

- Bare distilled small models are weak at this task without the paper's training pipeline: "The two distilled variants of DeepSeek R1—Qwen 1.5B and Qwen 7B—exhibit weaker performance overall, with high rates of no extracted JSON or large amounts of noise" (Section 4) — a cautionary data point that a size-matched off-the-shelf reasoning-distilled 1.5B model does not spontaneously do reliable schema extraction; training (RL+SFT) is what closes the gap.
- Even the strongest baseline, full DeepSeek R1 (671B), only reaches 41.43% mean match with 11.14% mean noise on this benchmark — general strong reasoning ability alone, at any scale, does not guarantee schema fidelity, reinforcing the project's premise that structured-output reliability needs a dedicated training signal rather than relying on general capability.
- The paper's own metric ("mean match percentage" of fields correctly mapped) is a soft/partial-credit metric, not a strict schema-valid pass/fail rate — this differs from the project's "first-attempt schema validity" binary metric, so ThinkJSON's headline numbers are not directly comparable to the project's target thresholds.

## Metric / eval choices

- Four extraction-quality metrics used: Rows With No Output, Rows With Valid JSON (syntactic validity), Mean Match Percentage (field-level correctness), Mean Noise Percentage (extraneous/malformed tokens) — a reasonable template for a richer eval than pure pass/fail, worth considering as supplementary diagnostics alongside the project's binary schema-validity metric.
- Reported headline results: ThinkJSON 62.41% mean match / 0.27% mean noise (best of 5 models); DeepSeek R1 671B 41.43% match / 11.14% noise; Gemini 2.0 Flash 42.88% match / 10.86% noise — all at a task/dataset not shared with this project's BFCLv3/IFEval suite, so numbers are context only, not directly transferable targets.

## Open questions for our project

- The approach uses an explicit `<think>...</think>` chain-of-thought block before the `<answer>` JSON — this adds generation-length overhead per turn, which is a concern for the project's throughput-floor requirement (4-bit decode within 5% of base) and general latency budget on an 8GB device; the paper does not report latency, token-count overhead, or any quantized/on-device evaluation of ThinkJSON.
- The paper does not test or discuss quantization at all, so it gives no evidence on whether this reasoning-augmented schema-adherence training survives 4-bit quantization — one of this project's central open questions.
- No discussion of general-capability regression (MMLU-style or instruction-following degradation) from the RL+SFT schema-training process — the paper only reports schema-extraction metrics, leaving open whether this recipe would erode the project's guardrail metrics (IFEval, MMLU-Pro, GPQA Diamond).
- Reviewed as a public paper describing a training pipeline; contains no text formatted as an instruction directed at a reader, so nothing was flagged as suspicious per the untrusted-data rule.
