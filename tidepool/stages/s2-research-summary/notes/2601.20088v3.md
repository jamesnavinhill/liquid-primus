# 2601.20088v3 — Quantization-Aware Distillation for NVFP4 Inference Accuracy Recovery

**Relevance:** high
Directly targets the last step of the project's candidate ladder ("quantization-aware distillation, then quantization-aware training if needed") and gives concrete loss/LR/data guidance, plus evidence on how quantization erodes instruction-following vs. knowledge and how to selectively quantize hybrid conv/attention architectures like LFM2.5.

## TL;DR

NVIDIA shows that distilling a full-precision "teacher" into its own NVFP4-quantized "student" via KL divergence (QAD) recovers near-BF16 accuracy far more reliably than standard quantization-aware training (QAT) with cross-entropy, especially for models that went through multi-stage SFT+RL post-training. QAD is also surprisingly robust to weak or even random training data, which matters if the project's own fine-tuning data is limited.

## Techniques to try

- Use the model's own full-precision post-trained checkpoint as teacher, train the quantized model as student with KL divergence at softmax temperature T=1, rather than task cross-entropy: "QAD uses the original high-precision model as a teacher to train the quantized model as a student using distillation loss." (Section 3.1)
- For hybrid conv/attention architectures (structurally analogous to LFM2.5's gated-conv + GQA blocks), keep attention layers (and a few adjacent layers) in higher precision and quantize the rest, plus quantize KV-cache separately: "we keep the 6 self-attention layers and their preceding Mamba-2 layers at BF16, quantize the remaining network to NVFP4, and quantize KV-Cache to FP8." (Section 3.4, on Nemotron 3 Nano)
- Learning rate guidance differs by how the base model was trained: "Overall, we recommend a learning rate between 1e-5 to 1e-6" — SFT-heavy models want LR at or below their original SFT LR (one VLM case needed 10x lower), while RL-heavy models need a notably higher QAD LR than their RL training used. (Section 4.2)
- Prefer KL divergence over MSE-on-logits as the distillation loss: "KL divergence consistently outperforms MSE across benchmarks." (Table 8, Section 4.3)
- Use the model's own weights as teacher rather than a larger sibling model — a 12B teacher underperformed the 9B model's own weights as teacher for distilling the 9B student. (Table 9, Section 4.3)

## Baselines & datasets used

- Post-trained models evaluated: Llama Nemotron Super V1 (49B), Nemotron Nano 9B V2, Nemotron 3 Nano 30B-A3B (hybrid Mamba-Transformer MoE), AceReason Nemotron 1.1 7B (Qwen2.5-based, RL-only math/code specialist — closest in scale to this project's model class), Nemotron Nano 12B v2 VL.
- Benchmarks: MATH500, AIME24/25, GPQA-Diamond, LiveCodeBench (v5/v6), SciCode, IFEval-Instruction, AA-LCR; VLM benchmarks AI2D/ChartQA/DocVQA/InfoVQA/OCRBench/TextVQA.
- Training data sources tested for QAD: original cold-start SFT data, BF16-model-generated data from RL prompts (with/without filtering to correct-only), data generated from a single BOS token, and fully random token sequences.

## Pitfalls / negative results

- QAT can match the teacher's validation cross-entropy loss almost exactly while still being badly misaligned with it: "QAT achieves nearly the same cross-entropy loss as the BF16 baseline... However, the KL divergence reveals a different story: QAD achieves nearly zero KL divergence, while QAT exhibits significant divergence from the teacher." Cross-entropy-matched loss is not evidence of behavioral fidelity. (Table 1, Section 3.1)
- QAT actively breaks capabilities learned during RL post-training when trained on cold-start SFT data: on AA-LCR, QAT dropped to 24.8 vs. BF16's 35.9 (worse than PTQ's 31.3), while QAD recovered to 34.3. "NVFP4 QAT breaks the RL model's capabilities... demonstrating the necessity of distillation for RL models." (Table 3, Section 3.2) — directly relevant since this project's ladder includes DPO/GRPO stages before quantization.
- Data budgets for QAD are large relative to what a small specialized project likely has: reported convergence needed ~0.3B tokens (49B model) up to ~6B tokens (9B model), and this is full-model distillation, not LoRA — none of the ablations here test parameter-efficient QAD. (Section 3.4, "Data")
- All results are on NVFP4, a hardware-specific block-scaled floating-point format (16-value blocks, FP8 scale + FP32 second-level scale) — not the same quantization scheme as a llama.cpp/GGUF INT4 format (e.g., Q4_K_M) targeted by this project's shipping requirement; the KL-distillation methodology likely transfers but the specific accuracy-recovery numbers should not be assumed to transfer directly.
- Smallest model tested is 7B (AceReason Nemotron); nothing at the ~1.2B scale of this project's target model is evaluated, so data/LR requirements may not scale down linearly.

## Metric / eval choices

- Checkpoint selection: evaluate the top 10 checkpoints by validation loss and pick the best average across benchmarks, rather than trusting validation loss alone (consistent with the paper's own finding that loss can be misleading). (Section 3.4)
- Heavy multi-sample averaging per problem to reduce eval noise: "48 runs for AIME 2024 and AIME 2025, 12 runs for LiveCodeBench, 20 runs for GPQA Diamond, and 5 runs for IFEval," at T=0.6, top-p=0.95. (Section 3.4)
- IFEval-Instruction is the only instruction-following-style metric reported; it degrades only modestly under PTQ/QAT/QAD (e.g., 87.5 BF16 → 86.9 PTQ → 87.2 QAT → 87.8 QAD for Llama Nemotron Super V1), offering a weak data point that instruction-following is not disproportionately fragile under quantization relative to knowledge/reasoning tasks — but this is not a tool-calling or JSON-schema-validity metric, so it only partially answers this project's open question about structured-output degradation under quantization.

## Open questions for our project

- Does the QAD (KL-divergence teacher-student) approach transfer from NVFP4 hardware quantization to the INT4/GGUF quantization scheme this project must ship, or does the block-scaled FP4 format's better error properties make QAD's gains partly format-specific?
- What data volume would QAD need at 1.2B scale, and is that volume feasible under "all training and evaluation runs as queued jobs on managed hardware" for a project this size, given the paper's smallest case still used ~0.3B tokens?
- Would QAD (or QAT) as a final quantization step erase or preserve the tool-calling/schema-validity gains from the earlier SFT/DPO/GRPO stages in this project's ladder, given the paper's finding that QAT can silently overwrite RL-trained behavior?
- The paper's finding that random-token training data still avoids "breaking" the model under QAD is encouraging for the "robust to incomplete domain coverage" question, but it was not tested with anything resembling structured tool-call/JSON output, so it is unclear whether it holds for this project's narrow output format.
