# 2601.13572v1 — Behavior Knowledge Merge in Reinforced Agentic Models

**Relevance:** low
The paper's whole contribution is a method for merging several separately RL-trained agentic models into one generalist checkpoint, but this project's standing constraints put ensembling/merging out of scope and target a single model specialized to one domain via a LoRA→SFT→DPO→GRPO ladder, so RAM itself isn't adoptable here.

## TL;DR

The paper shows that RL-induced task vectors (the parameter deltas from RL fine-tuning) are far sparser and more heterogeneous across tasks than SFT task vectors, so naively averaging several RL-trained agents together dilutes each agent's unique, task-specific parameter updates. They propose RAM, which averages only the parameter regions shared by multiple agents and preserves/rescales the regions unique to one agent, and show this beats Task Arithmetic/TIES/DARE/Fisher when merging a coding, a tool-use, and a long-context-memory agent (all starting from Qwen2.5-7B-Instruct or Llama-3.2-3B-Instruct).

## Techniques to try

- Not applicable to this project's plan — the technique is model merging across independently-trained agents, and "Ensembling is out of scope" per this project's standing constraints. No bullet carried forward for adoption.

## Baselines & datasets used

- Compares against Task Arithmetic, Fisher Merging, TIES-Merging, and DARE (+TA/+TIES variants) for merging RL-trained agents ("Task Arithmetic (Ilharco et al., 2023) ... TIES-Merging (Yadav et al., 2023) ... DARE (Yu et al., 2024)" — Section 5.1, Baselines).
- Evaluates on LiveBench/LiveCodeBench (coding), BFCL Live/Non-Live Parallel and Parallel-Multiple subsets (tool use — same benchmark family this project's pre-registered claim targets), and RULER-HotpotQA/RULER-SQuAD (long-context memory), all at 7B (Qwen2.5-7B-Instruct) and 3B (Llama-3.2-3B-Instruct) scale.

## Pitfalls / negative results

- Naive merging can badly damage instruction-following on smaller models: on Llama-3.2-3B-Instruct, TIES and DARE+TIES caused "-11.15" and "-11.27" point drops in IFEval Loose Instruction Accuracy relative to the un-merged base, versus RAM's much smaller "-2.51" ("RAM demonstrates superior robustness compared to TIES/DARE, especially on the smaller Llama-3.2-3B-Instruction model" — Table 3, Appendix C.2). This is a useful cautionary data point that aggressive parameter-trimming/merging methods degrade general instruction-following much more severely at smaller scale (3B) than at 7B — relevant context (not a method) if this project ever considers merging LoRA adapters trained separately for different objectives (SFT vs. GRPO reward heads) rather than a single sequential ladder.
- RL fine-tuning is characterized as extremely sparse and heterogeneous across tasks/domains: "the coding agent exhibits extreme sparsity, modifying only 3.2% of parameters. In contrast, agents optimized for tool use and long-context memory induce significantly denser updates, affecting 46.2% and 54.3% of the parameter space, respectively" (Section 3.2). This is a general observation about what GRPO-style RL does to parameters, not something this paper turns into an actionable pitfall for single-task training.

## Metric / eval choices

- Uses BFCL (Live/Non-Live, Parallel and Parallel-Multiple subsets) with AST-based structural matching as its tool-use metric, the same benchmark family (BFCL) this project's pre-registered claim is built on — worth noting only as confirmation that BFCL AST matching is a standard, actively-used protocol elsewhere, not as a new metric to adopt.
- Uses IFEval (Instruction Accuracy / Prompt Accuracy, Loose/Strict) as its general-capability regression check, again the same benchmark this project already targets for its guardrail metrics — no new eval technique here.
