# 2601.02151v1 — Entropy-Adaptive Fine-Tuning: Resolving Confident Conflicts to Mitigate Forgetting

**Relevance:** high
Directly measures SFT-induced catastrophic forgetting from an agentic tool-use dataset evaluated on BFCL v3 alongside MMLU/IFEval, which is close to this project's own axis (BFCL gain vs. guardrail budget), and offers a near-drop-in loss modification for the SFT rung of the candidate ladder.

## TL;DR

The paper argues SFT (unlike on-policy RL) forgets because it forces updates on "Confident Conflicts" — tokens where the model is low-entropy (confident) but low-probability (wrong per the label) — and that these tokens produce the largest, most destructive gradients. Their fix, Entropy-Adaptive Fine-Tuning (EAFT), multiplies the standard cross-entropy loss per token by that token's (top-20-approximated) normalized entropy, so confidently-wrong tokens get down-weighted while genuinely uncertain tokens train normally; tested on math, medical, and — most relevant here — agentic tool-use SFT with a Qwen3-4B model, evaluated on BFCL v3.

## Techniques to try

- Scale the per-token CE loss by normalized top-K predictive entropy instead of applying a KL penalty or uniform weighting: "$\mathcal{L}_{\text{EAFT}}(\theta)=-\sum_{t=1}^{T}\tilde{H}_{t}\cdot\log P_{\theta}(y_{t}|\bm{x},\bm{y}_{<t})$" (Sec. 3.3) — cheap to add on top of a plain SFT loop in a framework like LLaMA-Factory, no reference model needed.
- Approximate entropy over only the top-20 logits rather than the full 65K+ vocabulary to keep the overhead negligible: "at $K=20$ (green zone), the correlation reaches 0.999... the memory cost... remains virtually zero (<0.4 KB) for $K\leq 20$" (Sec. 5.2) — relevant given LFM2.5's 65,536-token vocabulary is on the same order they tested against.
- If doing a quick pilot/ablation before committing to soft gating, a hard mask on the bottom-15% (entropy, probability) tokens is a one-line sanity check, though the paper shows it costs target-task performance (see Pitfalls below).

## Baselines & datasets used

- Agent tool-use experiment: fine-tuned Qwen3-4B-Instruct on 20k sampled trajectories from "Nemotron-Agentic-Tool-Use-v1... non-thinking subset" (App. B.3), evaluated on BFCL v3 (~2K entries, AST-based evaluation) plus MMLU, IFEval, CLUEWSC as the general-capability battery.
- Baselines compared: plain SFT, SFT+KL-regularization (frozen reference model, "incurs significant memory overhead"), FLOW, DFT, TALR — all probability- or loss-based reweighting schemes that the authors argue can't distinguish epistemic uncertainty from confident conflict the way entropy can.
- Training recipe (Table 4, App. F): LLaMA-Factory, lr 1e-5 cosine, AdamW, batch size 64, 10 epochs, max seq len 16384, on 8x A100s. Not stated whether full-parameter or LoRA fine-tuning was used for the base SFT/EAFT runs — worth flagging as unresolved for adapting to a 1.2B model.

## Pitfalls / negative results

- On the agent tool-use task itself (Table 3, Qwen3-4B-Instruct), plain SFT nudged BFCL v3 up only marginally (60.5 → 61.4) while general average collapsed from 81.1 to 74.8 (-6.3), and specifically IFEval dropped 81.0 → 77.8 (-3.2) and CLUEWSC 85.2 → 72.2 (-13.0). EAFT roughly halved the damage (general avg 77.5, -3.6; IFEval 78.6, -2.4) but did **not** get IFEval degradation under this project's own 2.0-point guardrail budget, and BFCL barely moved (60.8 vs. baseline 60.5) — i.e. even the mitigated method still breached a 2-point-style guardrail on one of our exact metrics (IFEval) while buying almost no BFCL gain.
- Hard-masking confident-conflict tokens (discarding the bottom 15% by entropy and probability) prevents forgetting but "significantly harms target task performance (Math Score drops to 65.60 vs. EAFT's 69.27)" (Sec. 5.1) — a caution against naive token-dropping approaches to protect guardrails.
- Explicit scope limitation: "It is not a universal replacement for standard SFT, particularly in scenarios requiring knowledge editing or counterfactual training... In such cases, the model's resistance to 'Confident Conflicts' is undesirable, as the objective is precisely to override the prior belief. EAFT would interpret these necessary updates as conflicts and suppress them, hindering the intended learning." (Sec. 7) — potentially relevant if training "flag rather than assert" behavior requires overriding a confidently-wrong prior (e.g., a model that confidently accepts malformed tool output as valid); EAFT's gating could actively resist exactly that kind of correction.
- "if the base model exhibits miscalibrated confidence (e.g., being confidently wrong or hallucinating), EAFT inadvertently protect[s] these erroneous behaviors." (Sec. 7) — a second angle on the same risk for the malformed-tool-return flagging sub-criterion.
- Method never exceeds standard SFT on the target task by design: "EAFT achieves a Pareto improvement—maintaining high general capabilities while closely approaching, but not necessarily exceeding, the peak specialization performance of SFT." (Sec. 7)

## Metric / eval choices

- General-capability battery is MMLU, IFEval, CLUEWSC — IFEval overlaps directly with this project's guardrail set; MMLU is a proxy for (but not identical to) our MMLU-Pro target. CLUEWSC is Chinese-language and not applicable to this project's guardrails, but its outsized drop even under EAFT suggests general-capability degradation from tool-use SFT is uneven across benchmarks, not a single scalar.
- Agent-domain target metric is BFCL v3 overall score, same benchmark family this project targets, evaluated via "an Abstract Syntax Tree (AST) evaluation method" rather than string matching (App. C.4) — worth checking whether that AST scoring differs from whatever harness this project intends to use for BFCLv3.
- All results are averaged over three independent runs per config (App. F.3), a reproducibility practice worth matching given the project's tight point-based thresholds.

## Open questions for our project

- Would EAFT's entropy-gating actively work against the "flag rather than assert" objective, since that behavior likely requires overriding confidently-held (but wrong) priors about malformed tool output — exactly the case the authors flag as unsuited to their method?
- No experiments below 4B parameters; unclear whether the same entropy/probability distributional gap (and thus the same fix) holds at 1.2B scale, or whether a much smaller model's sharper/more brittle confidence distribution changes the picture.
- Training setup doesn't specify LoRA vs. full-parameter fine-tuning for the core SFT/EAFT comparisons, so it's unclear how directly this transfers to the project's LoRA-first rung of the candidate ladder.
- Even with EAFT, IFEval and BFCL movements were modest (a few points) at 4B scale — raises the question of whether entropy gating alone is strong enough to hit both a +3.0 BFCL gain and a ≤2.0-point guardrail hit simultaneously, or whether it would need to be combined with a data-mix or replay strategy.
