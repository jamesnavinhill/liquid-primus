# 2512.18934v1 — When Less is More: 8-bit Quantization Improves Continual Learning in Large Language Models

**Relevance:** high
Directly targets the project's open question of whether low-bit quantization damages capability more than it helps, and reports the counterintuitive finding that INT8/INT4 weight quantization can act as a regularizer that *reduces* catastrophic forgetting relative to FP16 during sequential fine-tuning, with concrete numbers at 8B scale using LoRA.

## TL;DR

The authors fine-tune LLaMA-3.1-8B with LoRA at FP16, INT8, and INT4 across a sequential NLU → Math → Code curriculum, sweeping replay buffer size from 0–20%. They find quantized models (especially INT8) retain prior-task accuracy better than FP16 once replay is added, and hypothesize quantization noise acts as implicit regularization against overwriting old knowledge. For this project, it's evidence that quantizing during/around specialization training is not purely a quality tax — it may interact favorably with how well general ability survives narrow fine-tuning.

## Techniques to try

- LoRA on top of quantized base weights (INT8 "standard inference-time weight quantization with LoRA adapters in higher precision"; INT4 "QLoRA-style NF4 quantization") as the adaptation method, matching this project's LoRA-first rung on the candidate ladder ("Model and quantization conditions." section).
- Track both forward accuracy (post-training performance on the just-learned task) and backward accuracy (retention of earlier tasks) separately when evaluating any specialization run, since the paper shows these can diverge sharply by precision ("reporting both average forward accuracy ... and backward accuracy" — Section 3).
- Use even a very small interleaved replay buffer of prior-domain data during specialization to cheaply protect general ability: "even minimal replay buffers (0.1%) dramatically improve retention—increasing NLU retention after Math training from 45% to 65% across all precision levels" (Abstract).

## Baselines & datasets used

- Base model: LLaMA-3.1-8B, LoRA rank r=8, alpha=16, dropout 0.0, 2e-4 LR, batch size 8 train / 32 eval, 1 epoch per dataset, single NVIDIA B200.
- Tasks: NLU (8 datasets aggregated from the LoRI benchmark — BoolQ, PIQA, SocialIQA, ARC-Challenge/Easy, OpenBookQA, HellaSwag, Winogrande), Math (GSM8K), Code (CodeAlpaca train → HumanEval pass@1 eval).
- Continual sequence: Stage A = 100% NLU; Stage B = 100% GSM8K + replay of NLU at B ∈ {0, 0.1, 0.5, 1, 2, 5, 10, 20}%; Stage C = 100% Code + replay of NLU and GSM8K at the same buffer sizes.
- Quantization via BitsAndBytes (INT8 PTQ-style weight quantization, INT4 NF4/QLoRA), following the LoRI benchmark protocol (Zhang_You_Panda_Goldstein_2025) for task setup.

## Pitfalls / negative results

- Without replay, quantized models forget catastrophically too, not just FP16: "under 0% replay, 4-bit models lost over 30% absolute accuracy on NLU (from 72.31% to 42.50% average), compared to ~35% for FP16 (from 77.26% to 42.50%)" — replay is still necessary, quantization alone doesn't save you.
- The regularization story is a hypothesis, not established: "We hypothesize that quantization-induced noise acts as implicit regularization... Further investigation is needed to validate this hypothesis" (Interpretation section) — treat the mechanism as unconfirmed even though the accuracy numbers are real.
- Explicitly flagged as a limitation: single model family/scale (LLaMA-3.1-8B only), only three uniform quantization levels (no mixed-precision/adaptive), "our experiments lack multi-seed runs and confidence intervals," and replay used only simple reservoir sampling — so none of the specific buffer-size percentages should be trusted as precise thresholds.
- All quantization here is weight-only PTQ/NF4 applied *before or during* LoRA training, not a post-hoc quantization of an already fully fine-tuned model to a GGUF artifact — the project's actual deployment path (train, then quantize to 4-bit GGUF) is not the scenario tested. Findings about "quantization during training aids retention" may not transfer to "quantizing a finished checkpoint for deployment."

## Metric / eval choices

- Forward accuracy = accuracy on the task just trained on; backward accuracy = retention of accuracy on previously trained tasks, both plotted against replay buffer size on a log scale (Figures 1–2) — a useful two-axis framing for any experiment that specializes the project's model while trying to preserve BFCLv3/IFEval/MMLU-Pro-style guardrail metrics.
- Code generation evaluated via pass@1 on HumanEval; NLU via per-dataset test-split accuracy averaged; Math via GSM8K test accuracy — all standard, all reported only at 8B.

## Open questions for our project

- Would the same INT8-as-regularizer effect show up at 1.2B parameters, or does it require the redundancy of an 8B model's weight space? The paper's smallest and only model is 8B, is a size the project should treat as an upper bound of applicability, not a guarantee it holds at 1.2B.
- The paper studies quantizing *during* continual LoRA fine-tuning, not quantizing a finished SFT/DPO/GRPO checkpoint to 4-bit GGUF for deployment — does the regularization benefit persist, disappear, or invert when quantization is applied only at the very end (the project's actual pipeline)?
- None of the tasks studied (NLU multiple-choice, GSM8K, HumanEval) involve structured tool-call output or JSON-schema validity, so this paper cannot directly answer whether quantization damages schema adherence specifically — it only speaks to general knowledge/reasoning retention.
- No instruction-following-style corpus or agentic reward loop was encountered in the paper; nothing here reads as directed at the reader, so no override of the standard reading was needed.
