# 2401.04151v1 — Chain of LoRA: Efficient Fine-tuning of Language Models via Residual Learning

**Relevance:** medium
Directly addresses the project's open "LoRA or full fine-tuning at 1.2B?" question with a zero-extra-cost way to narrow the LoRA/full-FT generalization gap, but all evidence is on small classification tasks (SST-2, WSC, CB, WIC, BoolQ, MultiRC, RTE) at rank 8, not on generation, instruction-following, or structured/tool-call output, so it is not validated for this project's actual prediction unit.

## TL;DR

COLA iteratively trains a LoRA module, merges it into the frozen base weights, then re-initializes a fresh LoRA module to fit the remaining residual — repeating this "tune, merge, extend" cycle several times within the same training budget. On OPT-1.3B and Llama2-7B classification tasks this consistently beats a single-shot LoRA run at the same rank and same total compute/memory, framed as a Frank-Wolfe-style residual-learning method with a nonconvex convergence proof.

## Techniques to try

- Chain-of-LoRA training loop as a drop-in replacement for a single LoRA SFT run at the same rank/epoch budget: "COLA forms a chain of LoRAs by iteratively tuning, merging, and extending LoRA modules" ("3.2 Chain of LoRA") — worth trying as a free upgrade to the "LoRA SFT" rung of the candidate ladder since it claims no added compute or memory.
- Rank step-down within the chain (start at rank 8, shrink rank in later links) to cut FLOPs while still beating fixed-rank LoRA: "COLA with rank step-down outperforms LoRA with a fixed rank of 8 for all tasks (with the exception of one data point–WIC with rank 2)" ("Rank step-down", Section 6.2) — relevant if the ladder needs a cheaper LoRA variant under a tight compute budget.
- Optimizer/adapter reset between links is called out as necessary, not incidental: "we reset all of the optimizer states, including but not limited to the parameters to be optimized and the gradient history" ("Extend the chain", Section 3.2).

## Baselines & datasets used

- Models: OPT-1.3B and Llama2-7B, both from HuggingFace checkpoints; LoRA rank r=8, alpha=16 in all experiments ("5.2 implementation details").
- Datasets: seven GLUE/SuperGLUE-style classification tasks (SST-2, WSC, CB, WIC, BoolQ, MultiRC, RTE), each with only 1,000 train / 500 validation / 1,000 test examples, following the low-data setup from Malladi et al. (2023) ("5.1 Models and Tasks", "5.2 implementation details").
- Sole baseline is standard single-shot LoRA at the same rank and epoch count; the paper itself notes "For future work, we will add in more baselines" ("methods compared", Section 5.1).

## Pitfalls / negative results

- Gains are small and task-dependent: on OPT-1.3B, COLA's biggest win is WSC at +6.47% relative (56.53→60.19 accuracy), but SST-2 improves only 0.17% relative and on Llama2-7B SST-2 shows exactly 0% improvement, "possibly due to the relatively low task complexity" ("6.1 Main Results").
- Optimal chain/rank configuration is task-specific with no clear rule: "the optimal rank to use for COLA is task-dependent... The WIC task, on the other hand, surprisingly shows maximal test accuracy at a rank of 4" ("Rank step-down", Section 6.2) — implies any adoption needs its own per-task rank sweep, adding tuning overhead not counted in the "no additional cost" framing.
- All experiments are 1000-example, 5-epoch classification setups on an A100 80GB; nothing here has been tested on generation, multi-turn agent turns, or JSON/tool-call structured decoding, so transfer to this project's prediction unit is unproven ("5.1", "7 Conclusions and future work": "We are also experimenting beyond classification tasks, namely generation, summarization, and multiple choice").

## Metric / eval choices

- Single scalar per task: test accuracy (or task-appropriate score) averaged over five random seeds, plus standard deviation reported in the chain-length ablation (Table 4) — COLA shows smaller std than LoRA on most tasks, framed as a robustness benefit ("6.2 Ablation Study").
- Training cost tracked via HuggingFace-trainer-reported FLOPs, used to show rank step-down configurations save compute while matching or beating fixed-rank LoRA (Table 3).

## Open questions for our project

- Would chaining/merging LoRA links on LFM2.5-1.2B's hybrid conv+GQA architecture behave the same way, or does the short-convolution component change which layers benefit from a residual LoRA update? The paper only tests standard attention-only transformers (OPT, Llama2) with LoRA on query/value projections.
- Does the "no additional cost" claim hold once BFCL/structured-output training data (not 1,000-example classification sets) and a full agent-turn objective are used, or does chaining need more merge/re-init cycles (and thus more wall-clock/scheduling overhead) to show a gap-closing effect on a harder task?
- No instruction-addressed-to-reader text was found in this paper; it reads as a standard research write-up throughout.
