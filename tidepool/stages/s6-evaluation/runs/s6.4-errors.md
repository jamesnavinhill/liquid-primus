# `s6.4` — the structured-output regression is mostly an unclosed code fence

Job `64f43caf`, CPU only, 0 GPU-hours, 0 assertion failures. Seven arms with staged
completions plus `B3` for the grader component alone. Nothing here generated a token: every
input is a file an earlier job wrote, and the completions were byte-checked against the run
whose verdicts are in storage.

Two earlier passes stand behind it and are kept in the ledger. `61131f2a` found a defect in
itself; `47cbb480` fixed it and returned the same headline numbers this pass returns, with two
tables too coarse to support the claims they were built for. Both are recorded in `budget.json`
with what superseded them.

## 1. The grader edit reclassified exactly one item, and it is named

| arm | shared items | flips | pre-edit | post-edit | observed | implied by flips | reconciles |
|---|--:|--:|--:|--:|--:|--:|:-:|
| B3 | 3490 | 1 | 0.5837 | 0.5786 | -0.005051 | -0.005051 | yes |

The item is `live_relevance_3-3-0#2`. It was right and is now wrong, on the reason string
`made no call when one applies`. A macro average over 11 categories moves by 1/(11n) when one
item flips in a category of n, and `live_relevance` has 18 rows, so 1/(11x18) = 0.005051 to six
decimals. The recomputed delta and the flip arithmetic agree exactly.

`B1`'s pre-edit per-item file was lost to the typed-save bug, so its row is a **prediction**
rather than an observation. Assuming it flipped on the same item gives -0.005051 against an
observed -0.005097 from the recorded 0.6700, a residual of -0.000046. A four-decimal recorded
figure carries +/-0.00005 of rounding, so the residual sits inside it and the prediction is
consistent with the record without confirming it.

**The `#2` matters and cost a job to learn.** BFCL v3 ships two different `live_relevance`
questions under the same id, `live_relevance_3-3-0`; the file has 3490 rows and 3489 distinct
ids. The reclassified item is the second of the pair. Pass one keyed the join on the bare id
and kept the first of any repeat, so it reported zero flips against a composite that had
visibly moved and failed its own arithmetic check rather than reconciling. Every join in this
job now pairs the kth occurrence with the kth, and asserts both files list their ids in the
same order (`same_id_order: true`). The comparison job at `s5.3` has paired by occurrence since
it was written, so **no recorded result was ever at risk.**

The flip carries one more thing worth reading. The old grader parsed one call out of that
completion and the new one parses none, on the same bytes. The edit changed what counts as a
call, not how a call is scored, and the mechanism is larger than the 0.005 it moved here.

## 2. Where the structured-output regression actually lives

Raw validity mixes two failures that want completely different fixes: the model did not
understand the requested schema, and the model understood it and did not close a code fence.
The grader raises exactly two envelope errors, so a failure whose entire error list is one of
them is a wrapper failure and nothing else. Dropping those items leaves **validity given a
clean envelope**, computed by the job.

| arm | format | validity | envelope-only failures | validity given a clean envelope |
|---|---|--:|--:|--:|
| B1 base | json | 0.2210 | 164 | 0.2644 |
| R3 | json | 0.1310 | 433 | **0.2310** |
| C7 | json | 0.2320 | 104 | 0.2589 |
| R3-Q4_K_M | json | 0.1130 | 393 | 0.1862 |
| B1 base | yaml | 0.0500 | 86 | 0.0547 |
| R3 | yaml | 0.0460 | 490 | **0.0902** |
| C7 | yaml | 0.0480 | 220 | 0.0615 |
| R3-Q4_K_M | yaml | 0.0340 | 516 | 0.0702 |

**On JSON, roughly two thirds of R3's regression is the wrapper.** Raw, R3 is 0.0900 below the
base. Conditioned on a clean envelope it is 0.0334 below, so 0.0566 of the 0.0900 is items
where the document was never given a chance to be judged. Nearly half of R3's JSON failures,
433 of 869, are envelope-only.

**On YAML the sign reverses.** Raw, R3 is 0.0040 below the base and reads as flat. Conditioned
on a clean envelope it is 0.0355 **above** it, 0.0902 against 0.0547 — a relative improvement of
about 65% on a small base. The reported YAML number understates what the tuned model can do
with a schema it is allowed to finish writing.

**It is not the token cap and it is not verbosity.** `hit_max_new_tokens` was 55 over R3's
entire run, and R3's median completion is *shorter* than the base's on both formats (993 against
1294 chars on JSON, 930 against 1114 on YAML) while carrying 432 unclosed fences against 161.
A model that runs out of budget produces long unclosed output; R3 produces short unclosed
output. The tuning taught it to stop, and it stops before the closing fence.

**The defect is R3's, not the recipe's.** C7, the other merge, has 104 envelope-only JSON
failures against the base's 164, and its conditional validity tracks the base within 0.006 on
JSON. C7 does carry the defect on YAML (220 against 86). Whatever produced it is specific to
where R3 and C7 differ, which makes it something a data or recipe change can reach.

This answers the paper-facing question directly. A large part of what has been reported as a
structured-output quality regression is a stopping-behaviour bug with a cheap fix, and the
honest version of the claim separates the two.

## 3. What the lost calls look like

Restricted to the 2350 call-warranted items, against `B1`, by grader reason family and by what
the model actually put on the wire.

| arm | lost | gained | net | prose only | emitted a call | top family |
|---|--:|--:|--:|--:|--:|---|
| R3 | 273 | 118 | -155 | 167 | 106 | did not call (167) |
| R3-F16 | 312 | 110 | -202 | 207 | 105 | did not call (207) |
| R3-Q4_K_M | 359 | 113 | -246 | 230 | 129 | did not call (230) |
| C7 | 188 | 144 | -44 | 77 | 111 | wrong arguments (82) |
| C7-Q4_K_M | 280 | 159 | -121 | 144 | 136 | did not call (144) |

**Not one item in any arm emitted nothing.** The models always answer; the question is whether
the answer is a call. For every R3 arm the dominant loss family is `did not call` — the model
wrote prose where a call was warranted — at 61% of losses on R3 and 64% on R3-Q4_K_M. C7 fails
differently: its largest family is `wrong arguments`, so it keeps calling and fills the call in
wrong.

That is the same finding as `s6.2` seen from the other side. The quantized arms lose 0.086 on
the eight call-warranted categories and gain 0.159 on the three where abstaining is right,
which nets to a flat pooled cell. Both halves are one movement: **the threshold at which these
models decide to call a tool moved toward abstention.** Quantization moves it further (R3 167
prose-only, R3-Q4_K_M 230), which is why the 4-bit arms look best exactly where saying nothing
is correct.

Collapsing the reason families is what made this table readable. The grader writes one clause
per ground-truth call, prefixed `gt<i>/call<j>:`, so read whole, every distinct function name
became its own family and pass two returned roughly forty singleton rows naming functions. The
prefix is stripped and the first clause decides, which is the difference between a list of
function names and an answer.

## Caveats

- `B3` has no staged completions, so its envelope and emitted-text columns are empty and the
  job says so in its notes rather than failing the pass. Its grader row is complete.
- `B1`'s grader row is a prediction and is labelled as one everywhere it appears.
- Conditional validity is a ratio on a shrinking denominator. R3's JSON conditional rests on
  567 clean-envelope items against the base's 836, so the two are not equally precise and the
  YAML reversal in particular sits on 510 items at a rate under 0.1.
